# src/docs-store.ts

- **src/docs-store.ts** + **src/docs-generated.ts** + **src/docs/** — Bernard's own manual, in one place with two readers: the `docs` tool serves it to the agent, and the website is built from the same files. Three levels, Agent Skills' shape with a tool call standing in for `Read` — `list` returns the index, `read` returns one document whole, and there is no third level. The `description` is the entire basis on which a document is chosen, so it must say what the document is AND when to reach for it.
  - **A topic is authored only when no declared record stands behind it (#584).** Where one does, the document is GENERATED and the prose wraps a live table: the colour and scale tokens, the brief's intent fields, the slash-command catalogue, the UI runtime's rule, the permission and planning mode tables, the model roles with their tier grid, and the settings registry. `applet-ui-runtime` is the standing evidence — it was migrated out of a hand-written `.md` **because that copy had already drifted** on the day it was written, and the base system prompt tells the agent to trust these documents over its own reconstruction, which makes a document the worst possible place for an unbound copy.
  - **`OPTIONS_REGISTRY` is deliberately not imported**, and the rule generalises: measured, `model-roles` ~2 ms, the three mode tables ~2 ms, `profiles-wizard-data` +21 ms (payable), **`config.ts` +85 ms (refused)** — above the 65 ms edge `docs-store.ts` already declines to take for one number. Every variable that registry would contribute already arrives as `WizardFieldData.envVar`. `lineups.ts`' `DEFAULT_TIERS` is left out for a different reason: those ids churn and that file says at length that catalogue membership settles nothing about whether a model is callable, so a manual naming a retired model is the hallucination class this corpus exists to prevent.
  - **The INDEX bound is what binds, not the 9,000-character body cap.** `parseDoc` returns the body after the front matter, so front matter is free; the index is a SUM over every row, and `MAX_INDEX_CHARS` was 2,000 with 1,656 already spent — one spare row, so a manual written against it fails on its second file, on an assertion naming whichever document was added last. It is 6,000 now, affordable only because the index is returned on a `list` CALL rather than carried in the cached prefix (which is why `docs.ts`'s `DESCRIPTION` deliberately does not enumerate documents). A sum needs a per-row ceiling too, so `MAX_DESCRIPTION_CHARS` is 220: without it one expansive description silently spends three other documents' share and the failure surfaces on an unrelated file. The finished manual measures **5,458 over 22 documents**, about 250 a row — so the headroom is two or three documents, and the right answer to the next one that does not fit is to cut a routing line rather than raise the bound.
  - **Four drift guards, in the direction that has actually failed.** `docs/manual.html` still names `BERNARD_REFERENCE_LOOKUP`, which #447 deleted with the module it gated — a documented setting nothing reads is worse than an undocumented one, because the reader changes it, nothing happens, and there is no error to search for. So no document may name a `bernard` subcommand, a `--flag` or a `BERNARD_*` variable that does not exist, every `.command()` must be documented or excluded through a `Record` carrying its REASON (`settings-coverage.test.ts`'s rule — requiring a sentence is the cheapest thing that makes a lazy exclusion visible in review), and `bernard-capabilities` must route to every other document, since with no search the router is the other half of discovery and it is the half that rots. Each was verified to bite; the coverage one found `set-max-concurrent` named nowhere on its first run, and the router one found `bernard-getting-started` on its first run.
  - **Commands are matched BACKTICKED, and two collisions are real rather than sloppy.** Prose legitimately says "ask bernard to check the deploy", so a bare-word scan reads `to` as a subcommand; and `bernard` is ALSO the JavaScript global an applet page calls, with `applet-page` quoting the browser's own `bernard is not defined` verbatim — verbatim being the entire value, since a reader greps the console text. That one word is excluded with its reason rather than by loosening the pattern, because every looser rule that skips it also skips a real reference (dropping three-token spans loses `bernard app list`, requiring a flag loses `bernard setup`). Separately, a backticked `--name` is ambiguous between a CSS custom property and a CLI flag, so the flag guard exempts one from the token guard: the two together now say that **every backticked `--name` is either a token the stylesheet serves or a flag the CLI accepts**, which is strictly stronger than either alone.
  - **Generating the CLI table from `src/index.ts` is disqualified**, and it is the obvious next idea. That module calls `migrateFromLegacy()` and `program.parse()` at MODULE SCOPE, so importing it from `docs-generated.ts` would run the legacy migration and parse `process.argv` in every worker dispatch and every test touching the corpus. Not fixable with a flag. `bernard-cli` therefore maps the families and names `bernard --help` as the complete list — which Commander renders live from the real table, so pointing at it cannot go stale where a 35-row document could.
  - **Seams fall at a change of VERB, not of subsystem.** "Does it remember me?" and "can I give it my PDFs?" split even though both are retrieval; cron and watchers split, and that one earns its keep twice, because `agent-prompt.ts` already spends a paragraph distinguishing them. `docs` has **no search** — `renderIndex` is the whole retrieval layer — so a document answering two unrelated questions gets one description line and loses one of them permanently. Voice, themes, tool detail and images get no document each: paragraph-sized, one shared verb, and each would cost ~200 characters of index for three sentences.
