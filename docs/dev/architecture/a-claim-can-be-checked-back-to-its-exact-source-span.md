# A claim can be checked back to its exact source span (#549).

- **A claim can be checked back to its exact source span (#549).** The location was already computed and thrown away: `quoteMatcher` returns a regex precisely so _"does it appear"_ and _"where does it appear"_ cannot drift apart, `windowAroundQuote` already called `body.search(matcher)` — the only place in the tree computing a quote's offset — and `quoteAppearsIn` then returned a bare boolean. `locateQuote` makes it the return value and `quoteAppearsIn` becomes a thin `!== null` over it, so every existing caller and test is untouched; the change is to what the search RETURNS, not to what it finds. The window consumes that offset rather than re-running the search, closing the drift the docstring exists to prevent by sharing the result rather than the regex.
  - **`Check` gains optional `sources` and `location`.** The ids are otherwise embedded in PROSE (`S1, S2: <reason>`), so anything going from a rubric row back to the source it names has to re-parse English. `renderRubricLine` is untouched — this adds an edge, it does not change what is rendered.
  - **`cite { action: 'locate' }`** returns the span plus a BOUNDED window, never the whole retained text: withholding that is the entire point of the field, and `get` strips it for the same reason.
  - **Three silent defects found while mapping it.** The RAG ref was `rag:<domain>:<first 60 chars of the fact>` — a lossy prefix of the CONTENT rather than an address, so two facts sharing sixty characters collided into one citable source and nothing could be looked back up; `RAGSearchResult` gains an optional `id` that `search()` had in hand all along and dropped. `web_read`'s `selector` was not in the dedup key (`${kind}:${rawRef}`), so two extractions of one URL collided and the longer body silently won — pinned at the PRODUCER rather than the store, since the first test asserted the store's key and the mutation survived: the store was never the part that was wrong. And retained text was set by **2 of 7 producers**; memory and scratch now set it too, which is **hardening rather than a bug fix** — measured, memory records are median 129 / max 1,039 bytes against a 2,000-char preview, so nothing exceeds it today. `locateQuote` reports `fromPreview` so a caller can tell "not found" from "not found in the first 2,000 characters".
  - **Two limits stated rather than discovered.** `REASONING_FAMILIES` never emit citation markers at all, so for `openai-reasoning` and `xai-grok-reasoning` there is no claim→source edge whatsoever and anything built on markers is a no-op — the same fail-open shape #372 recorded for the utility proxy. And only `research-agent` emits structured claims, so a plain sentence carrying a marker has an id but no quote; `cite locate` takes the quote from its caller and does not invent one.
  - **Cross-turn descent re-resolves from the ref rather than persisting the text.** `verifyText` is stripped on the way to disk, correctly: the provenance history is already 0.5 MB for 30 turns without it, and re-adding it would be ~20 KB per source per turn into a store with no cap.
