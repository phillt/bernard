# src/voice-service.ts

- **src/voice-service.ts** — `VoiceService` class: cross-platform TTS (darwin → `say`, linux → `spd-say`/`espeak-ng`/`espeak`, win32 → PowerShell System.Speech). Pure exported functions `resolveBackend` and `buildSpeakCommand` decouple backend selection and command construction from spawning (testable without side effects). All speech is non-blocking: the child is spawned with `stdio: 'ignore'` and `.unref()`ed so it never blocks the event loop or process exit, while `VoiceService` retains the handle so `stop()` can SIGTERM in-flight speech (called on `/voice off` and on profile switch). The REPL `/voice` command supports `on` / `off` / `status` / `test [text]` plus a bare-`/voice` interactive menu. **Sink warmup**: before each utterance the service plays a short silent WAV through an available player (`pw-play` → `paplay` → `aplay`, resolved by `resolveWarmupPlayer`) to wake a suspended PipeWire/PulseAudio sink so the first words aren't clipped while the device powers on; Linux-only (macOS/Windows keep devices awake), best-effort (any failure resolves silently and proceeds to speak), bounded by a safety timeout, awaited before speech, and cancellable mid-warmup via an epoch counter bumped by `stop()`. Duration is `config.voiceWarmupMs` (`BERNARD_VOICE_WARMUP_MS`, default 400, 0 = off). Pure helpers `resolveWarmupPlayer` / `buildWarmupCommand` / `buildSilenceWav` keep selection, command construction, and WAV generation testable without spawning. STT / voice-conversation mode is a planned follow-up.
