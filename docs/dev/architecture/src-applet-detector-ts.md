# src/applet-detector.ts

- **src/applet-detector.ts** + **src/applet-candidates.ts** — noticing that work would be better served by an applet than another chat turn (#430). Mirrors the specialist pipeline part for part rather than growing a parallel one, and the **cadence** is what makes it viable: it runs where `detectSpecialistCandidate` runs — the detached exit worker and `/clear --save` — so it costs the user no latency and sees a whole transcript, which is the only place "recurrence with structure" is visible. A per-turn detector would have been both more expensive and worse-informed. `checkOverlaps` is reused verbatim; **`computeConfidence` deliberately is not** — two of its four completeness terms read `systemPrompt` and `guidelines`, fields an applet candidate does not have and cannot be given without smuggling unrelated text into them, so an applet scored through it would sit 0.14 below a specialist on a component that says nothing about applets and the shared 0.8 threshold would be near-unreachable for reasons unrelated to quality. `appletConfidence` keeps the four **weights** identical, so both pipelines still mean the same thing by "0.8", and replaces only the term. `AppletCandidateStore` is a sibling of `CandidateStore`, not a generalization: they share six methods and an atomic write, and do not share the payload or `reconcileSaved`. **`autoCreateApplets` widens what is OFFERED, never what is built** — see `BERNARD_AUTO_CREATE_APPLETS`.
