# src/knowledge/

- **src/knowledge/** — ingested document libraries (#516/#517), the user's own corpus. Beside `RAGStore`, never replacing it: the codebase already wrote that rejection in `tools/docs.ts` — a 90-day TTL would make documentation evaporate and 0.92 dedup would drop similar paragraphs — and two more mechanisms finish it, a 5,000-record global cap a novel takes 40% of (after which `prune()` evicts the user's own conversation history) and a whole-file `JSON.stringify` on every write. This store has **no TTL, no dedup, no cross-owner cap and no whole-file rewrite**, and the last three are structural rather than absent: a library is a separate SQLite file, so there is no code path that could prune across libraries.
  - **Measured, and the numbers decide three designs.** The real 3,662-record conversational store re-encoded: **29.6 MB of JSON becomes 7.3 MB** (an embedding is 8,069 bytes as JSON text, 1,536 as a Float32 BLOB) and **193 ms to load becomes 7 ms**. Inserting 5,000 rows is **74 ms**; a full brute-force cosine scan over 5,000 is **27 ms** — so there is **no vector index, no `sqlite-vec`, no ANN**, which would be a new dependency for a problem that does not exist at this scale. Embedding is **12.9 ms per chunk, flat at batch 1 / 16 / 64**, so chunk-at-a-time progress is free.
  - **Ingestion is foreground with a progress line, not the detached `rag-worker` #517 proposes.** That worker is documented as silent by design, so the pattern the issue recommends is the one that cannot report progress on the one operation where progress is the whole UX. One transaction per SOURCE, which makes a 200-file ingest resumable for free: a run that dies on file 150 keeps 149, and re-running skips them by content hash.
  - **The character target is a planner; ingestion is the verifier, and it is not optional.** `MAX_EMBED_CHARS` divides by four, an English-prose average. Measured against the real tokenizer at a 700-char target: english 726 chars → **156** pieces, code 720 → **299**, Japanese 480 → **482**, against a ceiling of 256. So even at 700 a code chunk is 17% over and is truncated **silently** — the embedder returns a well-formed vector for a prefix with no error and no time penalty. `EmbeddingProvider.countWordPieces` is **optional**, because every existing test double implements three methods and a required fourth would break all of them for a capability only ingestion needs; a caller that gets `undefined` reports `verified: false` rather than assuming. The knob is the target for the WHOLE source rather than a per-chunk re-split, which keeps ordinals dense and offsets consistent. One tokenizer subtlety: `truncation: false` is what makes the count useful (with truncation on it reports the ceiling for anything over it, the case being detected), but the tokenizer then refuses a ragged batch outright, and padding would report the longest row's length for every row — so it counts one string at a time, microseconds against ~12.9 ms of inference.
  - **`chunk.ts`, `stitch.ts` and `ids.ts` are pure leaves with no imports at all**, like `lexical.ts`. `ids.ts` exists specifically to refuse an edge: `declaredScope` runs before EVERY dispatch including `main`, from a call site outside the only `try`, so the predicate validating a scope entry must not touch disk or throw. It validates **shape, never existence** — a well-formed id for a library that does not exist yet is KEPT, which is the difference from `knowledgeScope`'s predicate and the reason a library name in _that_ field resolves to `[]`, i.e. silent deny-all.
  - **`corpusScope` is its own dispatch-profile field**, not a reuse of `knowledgeScope`. Three verified reasons: that field's predicate is an existence check against the frozen domain registry; `declaredScope`'s call site is outside its only `try`; and `headless.ts` applies the knowledge fence ctx-free by calling `.scoped()` on the RAG store directly, so one array holding two namespaces needs a partition rule correct in **two** places or a cron run fences differently from an interactive one. Memory and knowledge were already two fields for two stores; a third store gets a third. **The corpus fence has exactly ONE application point** because nothing pre-searches the corpus — defended with a comment at the `headless.ts` construction, since a later pre-assembly search added for the MCP-overlap reason would need a second fence or the paths diverge invisibly.
  - **`KnowledgeCorpus` has no per-instance mutable state**, which dodges `rag.ts`'s shallow-clone trap rather than handling it: there is no field a `scoped()` clone could fork. The connection cache is module-level and the write generation lives on the store, which is never cloned. Constructing one opens no database, so a handle sits on every `AgentContext` without repeating the ~190 ms / ~128 MB `headless.ts` documents for `new RAGStore()`. `open()` is the single enforcement point, and out-of-scope and absent answer identically — naming a fenced library leaks the catalogue, which is `assets.ts`'s 404-not-403 reasoning.
  - **Retrieval reuses `src/lexical.ts` unchanged**, and the floor rule is the one thing easiest to get backwards. The cosine floor applies to the **dense channel only**: it is what stops a query matching nothing returning the corpus's k most arbitrary chunks, since an RRF score is ~1/61 for any rank-1 document under any query including gibberish. Applying it to the lexical channel too drops every lexical-ONLY hit — the entire population that channel recovers, and the opposite of `rag.ts`'s stated rule. Nothing is lost by leaving it off there: `LexicalIndex.score` returns only non-zero scores, so a term appearing nowhere contributes no candidates. Both directions are pinned.
  - **Chunks carry an `ordinal` and `read` returns neighbours in order** — #521's cheapest measured win, at one integer column. `stitch.ts` drops a continuation chunk's carried prefix once, marks a hole rather than closing it, and **re-emits a heading that CHANGED**: `prefixLen` covers heading and overlap together, and dropping it wholesale is right only for the overlap, so a window spanning two sections lost the second heading and read as one undifferentiated passage. The corpus eval caught that on the day it landed.
  - **The tool is `list` / `search` / `read` and deliberately no `add`.** Ingestion reads arbitrary local paths and arbitrary URLs, so an agent-callable ingest is an arbitrary-file-read primitive laundered through a store — read a file the write-scope gate would have refused, then "search" for it. `deterministic: false`, unlike `docs`, because an ingest in another terminal changes the answer and the result cache would serve the stale one for five minutes. It is constructed **only** when a corpus handle is supplied, so a tool that exists is a tool already fenced.
  - **`PRAGMA foreign_keys` is redundant here and the received wisdom is wrong.** The rule that SQLite defaults it OFF per connection is true of SQLite and false of this driver — `DatabaseSync` takes `enableForeignKeyConstraints`, which defaults to `true`; measured, a bare `new DatabaseSync(':memory:')` reports `1`. The line is kept as belt-and-braces and says so at length, because otherwise someone corrects the comment back and then relies on a pragma they think is doing the work.
  - **PDF takes `voice-service.ts`'s TTS-backend shape** — probe for `pdftotext` with the probe injected so the absent-binary path is testable — rather than adding a PDF parser to `dependencies`. **Code chunking is line-based, not tree-sitter**: `tree-sitter-wasms` is already a dependency shipping 36 grammars so it would cost nothing in dependencies, but its loader needs `createRequire` and a WASM read, which `chunk.ts` cannot have without giving up being a pure leaf. Line boundaries already capture the property that matters — they never split a statement.
  - **Known gap:** URL ingestion shares `src/html-text.ts` with `web_read` (extracted rather than copied, so the strip list cannot drift) but there is no `bernard knowledge add <url>` yet — only local files and directories. Adding it needs the fetch half, which `web_read` owns along with its timeout, user agent and size cap.
