# src/work-queue.ts

- **src/work-queue.ts** — the work queue behind both session-close passes that have one. A directory, one file per item, `<epochMs>-<seq>-<uuid>.json` so a lexical sort IS arrival order and a claim needs no `stat`. **At-least-once**: deletion is the acknowledgement and only SUCCESS calls it — the one inversion from `src/inbox/`, which unlinks whatever happens because it is deliberately at-most-once. Attempts are counted by `claim` **before** the consumer runs, so a drain that crashes between claiming and acknowledging cannot retry forever; an exhausted item is renamed into `parked/` rather than carrying a status field, because "what is still work?" is then answered by a directory without parsing anything. `sweep()` bounds it by age and count — the retention all four candidate stores lack, measured at 54 correction rows and 42 others on a real install with nothing that could remove them. **No in-memory pending counter**: `CorrectionCandidateStore`'s was a single-process optimisation, wrong by construction the moment a second writer exists, and measured it was not where the time went (enqueue 0.128 ms empty, 0.199 ms at 199 pending, against 0.0075 ms for `appendJsonlBounded`). `src/recall-queue.ts` and `src/correction-queue.ts` are the two consumers — each a leaf owning a directory, a validator and a cap, so neither producer acquires the `generateText` graph its drain lives beside.
  - **The `seq` is not decoration.** `inbox/send.ts` uses `<epochMs>-<uuid>` and tolerates same-millisecond ties because a notice's order among simultaneous arrivals does not matter. Here oldest-first IS the property that fixes the correction drain's starvation, and with a UUID deciding ties a four-item burst sorted `n1, n3, n0, n2`.
  - **`parkedAt` is stamped on the way out** and is what the prune ages against. Ageing a parked item by `enqueuedAt` deleted it in the same sweep that parked it FOR being old, so nobody could ever see the evidence.
  - **No "directory created this process" cache**, unlike `jsonl.ts`'s `readyDirs`: a drain EMPTIES this directory, so a cached `true` makes every later enqueue fail silently. It also bought nothing measurable.
