# An applet reports back (#461, #462, #456).

- **An applet reports back (#461, #462, #456).** Three gaps that only make sense together: a failure that left no readable trace, no way for anything to reach the running session, and no way for Bernard to act on the answer.
  - **The message was computed and thrown away.** `recordInvocation` logged `ok`, `errorCode`, `errorCategory` and argument KEYS, so the observed failure — `"No datetime tool available"`, the agent's own words, sitting in the browser where the user could read them — came back as `run_failed`/`unknown`. It needed no threading: `message` is a parameter of `fail()`, in scope at the log call and already used two lines later to build the envelope. Nothing had ever read that file either — no CLI, no tool, no panel — so `bernard app logs <id>` and an `applet` `logs` action are the two doors onto one reader.
  - **`invalid_args` is the one message that cannot be stored, and this was measured rather than assumed.** It is `formatZodError` over the CALLER's arguments, and zod echoes the value it rejected: `received 'hunter2'`. Storing it verbatim would put caller data in the log on precisely the path where the caller supplied it, breaking the keys-never-values rule the file otherwise keeps by construction. `loggableMessage` keeps the message for every other code and reduces that one to its field PATHS — argument names, already permitted — so "which field" is still answerable without the value. A test feeds a secret through an enum and fails if the reduction is removed.
  - **The issue named the wrong diagnostic field.** It calls an empty `toolAllowlist` "the single most common cause", but the motivating bug declared `toolAllowlist: ['datetime']` and got an empty INTERSECTION with the specialist's `targetTools` — which `toolsGranted` already recorded. Both halves are logged now and the gap is rendered at READ time by `uncoveredToolsMessage`, so the log explains itself. It also named `pruneFileGroupsByMtime` as the rotation idiom; that is for directories of per-group files, and `rotateJsonlByCount` was already in place.
  - **`bernard say` delivers a NOTICE and never starts a turn**, and that scope decision is what makes the trust question disappear rather than be answered: the text never enters `agent.history`, so it has no path to the model and the instruction-source boundary is structural rather than a policy every refactor must re-honour. Pinned by two tests — after delivery `processInput` was never called and the history is byte-identical. `kind` is on the wire and `capabilities` on the session record so a later billed mode fails loudly against an old REPL rather than being delivered as something it is not. **Still true under the default `ask`**, which is what keeps those two tests meaningful rather than deleted; the automatic modes are a decision the user makes.
  - **One keystroke acts on it, and the footer used to lie about that.** It read _"type to act on it"_ — false, because typing puts your words in front of the model and leaves the message where it was. Observed costing eight dispatches across two mail accounts and a chat bridge, with Bernard's own `think` recording _"User says Claude's blaze report is here but I can't see it in conversation"_, before the user interrupted. `Enter` on an empty prompt now runs the message; `^o` offers act-once / this-session / this-profile.
    - **It is gated by nothing, and that is the security argument rather than an omission.** Pressing a key on a message you are looking at is per-message human consent, which is strictly stronger than the blanket kind `--accept-remote-prompts` grants in advance to every local writer. So it widens nothing — it only makes the footer's existing promise true.
    - **The binding lives at `Prompt`'s own empty-buffer guard**, which has always been a silent `return`, not in a new `useInput`. Ink broadcasts every key to every mounted handler with no stop-propagation, so an App-level Enter binding would have to be arbitrated against the Prompt's; reusing the guard the Prompt already owns makes that question not arise. `^o` is a plain Ctrl chord for a measured reason: `MODIFIED_ENTER_RE` carries no capture group, so Shift+Enter and Ctrl+Enter are one keystroke to this process — and only the CSI-u family sends a modified Return at all, so on most terminals (gnome-terminal on libvte 0.68 included) Ctrl+Enter silently IS Enter and would act on the message instead of offering to.
    - **The pending message is deliberately NOT cleared when an ordinary turn runs.** That is the exact sequence this exists for — a message arrives, you say something about it, and only THEN want it acted on — and clearing there reproduces the failure. Enter on an empty prompt is otherwise a no-op, so holding the binding costs nothing, and `HintBar` shows the affordance only while it works. The panel's footer is frozen at arrival (Ink's `<Static>` never repaints an existing item), so it records what was true when the message landed, the way its timestamp does.
    - **A bordered title may not contain an emoji glyph, and all three panels did.** `⏰`, `✉` and `⚠` are one code unit and two columns, and Ink 5.2.1 pads the row against the larger figure — so the header rendered ONE column wider than every other row, the right border wrapped, and the corner was lost. Invisible until the box reaches the terminal's full width, which is why it survived from the day the panels were written and surfaced only when a long instruction pushed one to the edge. `stripAnsi(...).length` cannot see it; only `stringWidth` can, which is why no test caught it. They are now `◷`, `»` and `▲` — one code unit, `string-width` 1, not emoji, so nothing has a presentation choice to make.
      - **The rule is about ROWS, not titles, and `PlanPanel` is the proof.** Its done-step icon was `✔` — flagged by this module's own predicate — inside the prompt's border, which is the one bordered box on screen at all times; it broke the moment a step completed. `glyph-width.ts` looked straight at that file, said its fixed icon cell buys alignment rather than width, and then fixed three titles and not the icon. It is `✓` (U+2713) now, and the frame test carries a `PlanPanel` fixture.
      - **An untrusted LABEL is stripped; an untrusted BODY is not, and the line between them is ownership.** `sourceLabel` comes from `bernard say --source` and lands in a panel TITLE, so `--source '⚠evil'` broke the frame exactly as the hard-coded titles did (measured `[60, 61]`); `sanitizeSourceLabel` drops flagged glyphs, which decides nothing that function had not already decided — it truncates the label and collapses its whitespace, because a label is a claim rather than content. A message body, and the arbitrary tool results `SourcesViewer`/`ContextViewer` render inside cards, are somebody's content: the same break, needing a strip-or-keep decision that is its own change. Known gap, and the enforcement test's fixtures must use a hostile label rather than a hard-coded one, or they check the literal in the source instead of the string that reaches the terminal.
      - **`\p{Emoji}` is the discriminator, and the obvious alternative is wrong.** `\p{Emoji_Presentation}` reads like the property for this and is **false** for `✉` and `⚠`, which default to text presentation and break anyway. A blanket "anything `string-width` 2" rule is worse: it catches CJK, which is two columns and one code unit and lays out correctly already.
      - **It is a refusal, not a repair, and that cost one wrong fix to learn.** The first attempt appended U+FE0E (text presentation) so Ink's two measures agreed — every row then measured correct, and it made the frame **worse on a real terminal**: VTE honours the selector by drawing the glyph in one column while Ink still allocates two, so the header came out one column SHORT and the border broke the other way. Both halves were measured; only one measured the thing that decides it, which is what the terminal paints. There is no repair available, because two independent programs are choosing a width for one character and we control neither — so the rule is enforced by a test over the panels' rendered headers.
      - **Containment does not fix it either**, which is worth knowing before reaching for the tidier-looking option: `width="100%"`, `flexGrow`, `wrap="truncate"` and a fixed-width icon cell were each measured and each still emits 41 in a 40 box. `PlanPanel`'s fixed icon cell therefore buys column ALIGNMENT, not frame width — its comment is about locales and should not be read as a defence against this.
    - **`^o` opens the MODE menu when nothing is pending**, and that is not a convenience. Gated on a pending message the chord went dead the moment it was used: an automatic mode means no message is ever pending again, so the one surface offering "…and on this profile" vanished exactly after the session row had been taken — a one-way door, found by walking it. `/agent-options` was always the standing answer, and a keystroke nobody can find is not one.
    - **An automatic mode is disclosed in the hint bar** (`^o messages: all`), which the default `ask` is not. It is a state worth saying out loud on its own terms — any local process that can write the state directory can start a turn in this session, and nothing else on screen says so — and it doubles as the signpost back to the control.
    - It goes through `requestTurn`, never `runAgentTurn`: a keystroke landing mid-turn must queue rather than hit the silent `submittingRef` guard. That also buys the `WakePanel` provenance row and `announced: true`, so the instruction is attributed to its sender and never painted as a `❯` user bubble.
  - **A file inbox, not a loopback listener** (`src/inbox/`). The HTTP option has the better in-repo reference and that is its only advantage: loopback is not a permission boundary, so it needs a token, which lives in a `0600` file, so it ends up depending on the filesystem ACL the inbox uses directly — plus a port, a listener and more state. A held-open listener is the documented hang class (`host/client.ts`). And the stale-entry asymmetry decides it: **a recycled port can hand your payload to a stranger; a recycled PID can only fail to receive.** That is why `kill(pid,0)` liveness, which `host/client.ts` rightly calls the weaker option for a server, is the right one here. Two directories so each `readdir` has one meaning; one file per session because `atomicWriteFileSync` makes a write atomic, not a read-modify-write; the DIRECTORY is watched because a rename replaces the inode; the watcher and its interval are `unref()`ed so a missed `stop()` can never be why the process will not exit.
  - **`sanitizeNoticeText` is the security-critical part and it is new work.** This is the first path putting another process's text into Ink, which may own the alternate screen buffer, so untrusted CSI/OSC could move the cursor, clear the screen or set the title. Nothing in the repo stripped control characters (`normalizeToolText` repairs Unicode — a different job). Removing ESC removes the class; newlines survive because a message is prose. Applied on the way out AND in, since anything that can write the directory can write the file. `isMessageFile` is `endsWith('.json')` because `atomicWriteFileSync` writes its temp file **in the watched directory** — a looser predicate reads half-written messages.
  - **The panel is deliberately not `pushAssistantNotice`**, which renders behind the assistant's `❮` chevron and would let any local writer appear to be Bernard speaking. It takes neither chevron — `❯`/`❮` are the transcript's whole voice vocabulary — is boxed and left-aligned where user messages are unboxed and right-aligned, names its source at the same dim weight as the timestamp (it is an unauthenticated claim, never styled as verified), and ends with the load-bearing row, which states a fact and names no key: it is frozen in the transcript, so an instruction there is still offering a keystroke on every message already acted on or superseded. `HintBar` owns the affordance, because it is the only surface that can stop saying it. Nothing queues, because a queue protects a singleton and a notice contends for none.
  - **`StaticItemView` exists because there are two transcript surfaces** and TTY detection picks which a user sees, so a variant added to one is broken for half the users and invisible to whoever wrote it. Extracted as a pure refactor first, with a test asserting both surfaces render an item identically.
  - **A per-call risk hook that can RAISE (#456).** `riskFromMeta`'s only arg-aware branch produced exactly one value, `'low'`, so nothing could say that ONE action is more dangerous than its tool — `applet` is `write`+`local` → `medium`, and `confirmMode: 'auto'` prompts only on `high`. A static `meta.risk` cannot express it either: it wins outright, so raising the tool would prompt on `list` too. `ToolMeta.riskForCall` sits after `meta.risk` (the more deliberate statement still wins) and before `isWriteAction` (a statement about THIS call beats the generic downgrade), with `attachActionMeta` gaining `highRiskActions` to mirror `readActions`. It is on `ToolMeta` and **not** behind `actionScoped`, because `routine`/`specialist`/`lineup_edit` are documented non-adopters of that flag with the same destructive-`delete` shape. `risk.test.ts` states the whole precedence in one test, since the ORDER is the contract. Correction to the issue: `headlessToolOptions` does not omit `confirmAction` — it always supplies one and `resolvePosture` auto-denies above the threshold; the field that fails closed by omission is `blockAction`. So `high` yields the interactive prompt AND the headless auto-deny for free.
