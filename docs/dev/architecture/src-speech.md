# src/speech/

- **src/speech/** — talk mode (`/talk`) and cloud voices: a hands-free spoken conversation, with ElevenLabs as the first vendor and a registry so it can be swapped.
  - **ElevenLabs is a SERVICE, not an LLM provider.** Its only LLM surface is the Agents platform, which _calls_ an LLM; there is no completion endpoint to call. So its key lives in `SERVICE_KEY_ENV_VARS` (`config.ts`), beside `PROVIDER_ENV_VARS` and deliberately not in it: that table is iterated by everything meaning "an LLM I can run a turn on" — key status, the setup hub's "at least one keyed provider" check, the default-provider pick — and a speech key must satisfy none of them. Same `keys.json`, same 0600 write, same `bernard add-key elevenlabs <key>`; `getServiceKey` reads the file, then `ELEVENLABS_API_KEY`. `bernard providers` lists services in their own section.
  - **The swap point is `registry.ts`**: a `SpeechProvider` offers `synthesize`, `transcribe`, or both, and nothing that speaks or listens names a vendor. A new vendor is one file beside `elevenlabs.ts` and one entry. The ids live in the zero-import `ids.ts` because `config.ts` validates `voiceSttProvider` and the registry imports `config.ts` for keys; the registry is typed `Record<SpeechProviderId, …>`, so an id with no entry is a compile error. `elevenlabs.ts` is plain `fetch` — no SDK left behind when it is swapped — and surfaces the vendor's response body, since "401" alone sends the reader to the wrong fix.
  - **A cloud voice is a `VoiceBackend` value**, so the `/voice` picker lists it with no new UI. It resolves to a local PLAYER (the sink-warmup players, `pw-play` → `paplay` → `aplay`) rather than a speech binary; `VoiceService` takes the vendor as an injected `Synthesize` function, because `voice-service.ts` is a leaf and the vendor imports `config.ts`. Audio is requested as raw `pcm_22050` and piped to the player's stdin, so no mp3 decoder is needed. The sink warmup runs DURING synthesis rather than after it.
  - **`speak()` resolves to `'finished' | 'cancelled'`** on both paths. It used to resolve identically when superseded, and a talk loop has to tell "the person heard the reply, their turn" from "something else took over".
  - **The microphone is a system recorder** (`recorder.ts`: `pw-record` → `parec` → `arecord`, raw s16le 16 kHz mono on stdout), the `resolveBackend` probing shape. stdin is `'ignore'`, never inherited — Ink owns `process.stdin`. Linux only; macOS/Windows are a row each.
  - **End of speech is energy-based** (`endpointer.ts`, pure): 30 ms frames against a noise floor calibrated from the room and adapted during silence, ~900 ms of silence ends an utterance, a 90 ms start window ignores clicks, 300 ms of preroll keeps the first word. 60 s cap per utterance, and two minutes of silence ends the session, so a hot mic cannot record forever.
  - **The loop is `conversation.ts`, React-free, every effect injected.** Half-duplex: the mic is closed while Bernard speaks, which is what stops it transcribing itself; barge-in needs echo cancellation and is a follow-up.
  - **The mic stays open while Bernard THINKS**, because a pause to think ends an utterance before the thought does. A follow-up said then goes through `followUp` → `agent.interject`, the same door as text typed mid-turn (#200), with no silence timeout on that mic (a long turn is not the user going quiet). One the turn never reached — `takeUndeliveredInterjections` in `runAgentTurn`'s `finally` — goes back to the loop through `queueFollowUps` instead of `requestTurn`, so it runs AFTER the reply is spoken; a queued turn would answer silently, since readback is off in talk mode. Transcriptions still in flight when the turn ends are awaited and land in `pending`, never in a finished turn. The follow-up mic is closed before speaking, so half-duplex still holds. An empty transcript listens again and starts no turn; two consecutive transcription failures end the session with the reason (a bad key would otherwise loop forever).
  - **`/talk` leaves Enter to the person; `/talk hands-free` is the loop above, opted into each time** (`dictation.ts`), because an utterance ends at the first long-enough pause and the loop submitted it — mid-thought, often. Hands-free stays the goal, which is why it is an argument rather than a setting: nothing persists it until it is ready. Each piece goes into the composer through `Prompt`'s `DictationDoor`: a mutable object rather than a prop, since insertion is an event and a prop would re-insert on the next render, with a `held` list a mounting Prompt drains so a piece said while a full-screen overlay replaces the prompt is not lost. The mic stays open while a piece transcribes (nothing is speaking, so there is no echo, and closing it would clip the next sentence); transcriptions start at once and deliver in order. Replies are always read aloud in this mode, whatever `voiceTts` says — that is what talk means — and the mic is paused for them, the same half-duplex rule. It refuses without a voice backend, as hands-free does. `insertWordsAt` (`line-geometry.ts`) adds a space only where a piece would touch a word.
  - **Narration is the default, `minimal` the opt-out, both per session** (`narrator.ts`). The `Narrator` reads the same stream the transcript does — the sink is the message store plus it — collects the main agent's text per step and hands it over at the step's first tool call, which is the moment the sentence is complete; the final step has no tool call, so the reply is never said twice. Sub-agent text (an `agentLabel`) and reasoning never reach it. The model is asked for those lines through a `<voice_mode>` context section rather than the system prompt, so toggling talk does not move the cached prefix (#269). Talk speech goes through one queue (`speakQueued`) because `startSpeech` supersedes what is playing, which would cut a narrated line off with the reply; the queue keeps every mic shut from the first line to the last, including hands-free's follow-up mic via `holdFollowUps`.
  - **Speed is four names over the same `voiceRate`** (`voice-speed.ts`): wpm for local engines, a 0.7–1.2 multiplier for ElevenLabs, `regular` being no rate at all. A hand-typed rate reads as the nearest name. **Spaced by ear, not evenly**: measured against ElevenLabs, 1.1 shortened a clip ~5% and could not be heard, 1.15 ~12%, and 1.2 — the vendor's ceiling — ~27%, so Fast is 1.15 and Fastest is 1.2 plus a local 1.25× through ffmpeg's `atempo` (`changeTempo`), which keeps the pitch where replaying at a higher declared rate would not. Best effort like the sink warmup: no ffmpeg, or a failed run, plays the clip as synthesized. Measured at ~170 ms for a three-second clip, async so the render loop never waits on it. `voice_settings` is sent only off the voice's own pace, since it replaces the voice's stored settings rather than merging.
  - **Cloud voices are picked, and tuned, from `/voice`** (`speech/tuning.ts`). `listVoices` reads `/v1/voices`, which a restricted key needs the "Voices: read" permission for — the 401 says `missing_permissions` and the picker names the permission and falls back to a typed id, which needs none. `voiceTuning` (stability, similarity, style, speaker boost) is named steps over ElevenLabs' 0–1 `voice_settings`, every field optional. **Settings are merged, never sent alone**: the API takes `voice_settings` as a whole replacement, so the voice's stored settings are read once per voice (`/v1/voices/{id}/settings`) and what Bernard sets is laid over them; a failed read sends only the requested fields rather than failing the utterance. Untuned at the voice's own pace sends nothing and reads nothing.
  - **App wiring.** `/talk` refuses up front, naming the fix, with no recorder, no key, or no voice. A turn is `runAgentTurn(transcript)` — the transcript renders as an ordinary user bubble, because it is the user's words — and the reply is read off history. The post-turn readback is skipped while talk mode is on, or every answer would be spoken twice. Esc ends talk mode, busy or not; `/talk` is in `BUSY_ALLOWED_COMMANDS`. The hint bar shows the phase (`● listening`) ahead of everything but an overlay, because a live microphone is the one state that row must never leave unsaid. The first start per session says audio goes to ElevenLabs.
  - **A test fake that delivers mic data from microtasks hangs the suite**: the loop reopens the mic from inside the chain, so the test's own `setTimeout` ticks never run. The fake delivers on a macrotask, as a real recorder's stdout does.
  - **Not verified live**: the ElevenLabs round trips (no key on the machine this was built on). Mic capture, endpointing on a real room, and raw playback through `pw-play`/`paplay` were.
