# src/apps/

- **src/apps/** + **src/script/** — `bernard script`, the programmatic entry point (#419). `bernard script --app <appId> --action <name> --args '<json>'`; the caller supplies **an app id, a named action and typed arguments, never a prompt**. That is the security boundary, not a convenience: a string crosses as _instruction_, read by a model holding the user's tool authority (Hardy's confused deputy — the attacker supplies the designation, the agent supplies the authority), while a named action crosses as _data_ and one the caller invents simply does not resolve. The published name is the Action-Selector Pattern (arXiv:2506.08837); OWASP LLM06:2025 recommends it directly. #420 hardens this — opaque capability handles, TTL and use counts, session binding, provenance tagging, and persisted per-app permission rules — and `ResolvedInvocation` is written down with one producer today precisely so that landed as an addition rather than a rewrite.
  - **`manifest.ts`'s arg types are a tiny closed set, not JSON Schema.** An open schema language re-opens what the named action closed. `number`, `boolean` and `enum` admit no prose at all, so an action built only from them is **structurally uninjectable** — prefer that shape; a test feeds an injection string to each of the three and expects rejection. `.strict()` on every object is load-bearing: a misspelled `toolAllowlist` silently ignored yields an app that reads as scoped and is not, and on a call it stops a caller smuggling a `prompt` field alongside the declared args. Manifests are validated on **read**, not only on write — the file is user-editable between runs, so a write-time check alone is a time-of-check/time-of-use gap (#420 R6's complete mediation).
  - **Resolution is split from dispatch.** `src/apps/invocation.ts` (`ResolvedInvocation`, `InvocationFailure`, `resolveFromManifest`, `renderArgsBlock`) reads the registry, validates args and freezes a record, depending only on `manifest.ts` + `registry.ts`; `dispatch.ts` reaches the whole agent runtime through `runHeadless`. Together they made asking a pure question cost a full agent-runtime import, and made the tests mock the tool registry to exercise functions that never touch a tool — the edge `tool-bytes.ts` and `mcp-names.ts` exist to refuse. The split is also what #420 needs: its capability mint, a manifest lint and a validation endpoint on the #428 host all want to resolve without running.
  - **Two channels.** `action.instructions` is author-written and is the only thing in the instruction slot; the validated args travel separately as a labelled, fenced JSON block. The banner on that block is documented in code as a **mitigation, not the control** — prompt-level framing is known-insufficient. The load-bearing property is that `buildActionTools` grants the **intersection** of the action's `toolAllowlist` and the specialist's `targetTools` on the `'worker'` surface, so an action can narrow what the specialist already targets and never widen it: the agent can be fooled and still cannot act. The injection test asserts on the resulting registry, not on model behaviour.
  - **Dispatch reuses `toolWrapperDefinition` through `runHeadless`, not `dispatchToolWrapper`.** That path takes an agent-pool slot, writes the reasoning log, and — the disqualifying part — enqueues correction candidates on failure. An external caller's failed invocation must not shape a local specialist's few-shot examples; that queue was designed for the user's own mistakes. `skipPermissions` is deliberately absent from the manifest schema: an app must not be able to declare itself exempt.
  - **stdout purity is structural.** `withStdoutRedirectedToStderr` (`src/script/stdout-guard.ts`) wraps the run, because `src/tools/augment.ts` writes to stdout from inside any dispatch that records a profile error and is reachable from every tool an action can call — auditing print sites does not survive contact. Captured unbound so the restore is identity-preserving (binding would accumulate wrappers on nesting), restored in a `finally`. The single JSON object is written afterwards on a restored stdout.
  - **One failure path, and one exit-code table.** `EXIT_FOR` maps every `ScriptErrorCode` to its status, so adding a code is a compile error until its exit status is decided; the predecessor compared `code === 'run_failed' || code === 'timeout'` inside the pre-dispatch helper, where neither value can occur, so the arm that looked like the classification rule was dead. A single `fail()` owns the envelope and the log row — the three hand-rolled copies it replaces had already diverged, one classifying the wrapper error twice against two different strings, so the category in the log could disagree with the one handed to the caller for the same failure. Only a failure that actually ran gets a taxonomy category: classifying "No such app" yields `unknown`, which is noise dressed as a diagnosis. `src/index.ts` is correspondingly a declaration shim over `scriptMain`, like every neighbouring subcommand; it previously hand-rolled two envelopes of its own that omitted `invocationId` and `durationMs`.
  - **Three exit codes**: `0` success, `1` the work failed, `2` the _request_ was wrong — unknown app or action, unparseable args, a schema violation, or an action naming a specialist that does not exist (a pre-flight, so a broken manifest costs no model call). An applet host needs to tell "my integration is broken" from "retry might help". `--timeout` may only **shorten** the action's clock, never extend it — the budget belongs to the app, not the caller. `--args-file -` reads stdin, keeping values off `ARG_MAX` and out of `ps`. `--describe` prints the action schemas without dispatching, which is what a host reads to build its buttons. The invocation JSONL at `SCRIPT_LOG_FILE` records arg **keys only, never values**, and carries an always-null `capabilityId` so #420's mint↔invoke correlation is a value fill rather than a schema migration (R9).
  - **Manifest revisions are a union, never a bump.** `AppSchemaVersionSchema` accepts `1` and `2`, because `AppManifestSchema` is `.strict()` in both directions: an older binary meeting a field it does not know rejects the **whole app**, and a newer one must still read the v1 manifests on disk. v2's `AppAction.dispatch` is a discriminated union; a v1 manifest's flat `instructions`/`specialistId` are **lifted into the agent arm on read**, so nothing downstream branches on the version and no file is rewritten. Declaring both forms is rejected rather than merged — they can disagree — and `dispatch` on a v1 manifest is rejected too, so a manifest cannot half-declare itself. The refinement and the lift both hang off **`AppActionSchema`**, not off the manifest: that schema is exported and parsed directly, and when the rules lived on the manifest alone a bare action parse skipped every one of them _and_ the lift, yielding `dispatch: undefined` typed as `AppAction` — the exact shape this is meant to make unrepresentable, invisible because `tsc` excludes tests. Only the `schemaVersion < 2` gate stays on the manifest, since after the lift every action has a `dispatch` and the question is no longer answerable — which is why the manifest's `actions` record holds the raw schema.
  - **An action may call a tool directly, with no model (#445).** Three tiers: pure computation belongs in the applet's own JavaScript, judgment needs an agent, and **effects on the machine with a known shape are a function call**. Only the third existed. Paying a model to move a file is not only waste, it is _nondeterministic_ — an agent may skip a file or invent a path, where a loop does neither. Eligibility is `ToolMeta.directInvocable`, an **opt-in flag on the tool** beside `actionScoped` and declared for the same reason (a separate name list can disagree with the tool it describes, and here the disagreement is fail-open); an allowlist, not a denylist, so a tool added later is ineligible until someone deliberately marks it. Granted to `file_read_lines` / `file_write` / `web_read` / `web_search` / `memory`, and since #588 to `file_edit_lines` and `time_range_total` as well. **`shell` never gets it**, and the guard is an invariant rather than a name: `meta-coverage.test.ts` walks the constructed registry and fails on any `directInvocable` tool classified `dangerous`, or taking an argument a manifest cannot express — the shape check alone would admit `shell`, whose `{command: string}` is a perfectly representable scalar.
    - **The arg vocabulary is a table, and nesting is what it bought (#588).** `file_edit_lines` and `time_range_total` were excluded from this tier **not because they are unsafe** but because `ArgSpec` produced only scalars and both take nested arrays — so an applet could overwrite a whole file with no model and had to pay for an agent to edit three lines of one. That is the more common operation, the cheaper one, and the one where an agent's nondeterminism actually hurts; it also pushed authors toward `file_write` with whole contents, losing the `old_hash` check and clobbering where there was a patch. `src/apps/arg-types.ts` is the registry: one entry per type declaring its schema fragment, its validator, its cross-field rules and its page control, with `list` and `object` added as two of them.
      - **Adding a type is one entry**, one line in `ArgTypeId`, and the two sentences in `applet-data-planner`'s prompt and `docs/applet-actions.md` — because a prompt that lists an artefact is a second copy of it. Everything else derives: the enum at every level, the cross-field rules, the validator, the version demand, the starter page's control and the key-ownership map. **`ArgTypeHandler.check` exists so a rule only one type has does not become the `switch` this replaced wearing a different hat** — the object field-count bound lives on `object`'s entry rather than as an arm in `checkArgSpec`. The two places that do branch, branch on a closed vocabulary the table owns: `page-template.ts` on the control's `tag` to build markup, and the generated page script on `data-decode`, whose arms are pinned to the declared decoders. The drift that is left is checked: an id in the union with no entry is a **compile error** (`_everyArgTypeHasAnEntry`, in production code because `tsconfig.json` excludes tests, the #509 idiom), a prompt naming a type the table lacks or omitting one it has fails `bundled-manifest.test.ts` **in both directions including the stated count**, and a declared decoder with no arm in the generated page fails `page-validate.test.ts`.
      - **Bounded depth, not `z.lazy`.** Nesting is `MAX_ARG_DEPTH = 3` container hops, expanded eagerly, with the nesting types dropped at the deepest level. A bounded grammar is _more_ closed than a recursive one — the expressible shapes stay enumerable, which is the property the closed set exists to keep — and `applet.ts` advertises this schema to a model through `zod-to-json-schema`, which the AI SDK calls with `$refStrategy: 'none'` (read off `@ai-sdk/ui-utils/dist/index.mjs:1573-1576`, where `useReferences` defaults to `false` and nothing in `tool()`'s path sets it) — so a `$ref` encoding is not available to share a repeated level, and `z.lazy` would emit `$ref` cycles into a provider tool definition (#341's hazard class, one level up). Load-bearing rather than stylistic. **3 is not a round number**: it is exactly what `file_edit_lines` needs, `delete` included, and a bound of 2 would leave that tool **entirely** ineligible rather than partly usable, because `isRepresentableParam` refuses a parameter whose _deepest_ leaf a manifest cannot reach and one unreachable leaf disqualifies the whole tool.
      - **The cost is measured, and it is the reason for two knobs.** The level-0 JSON Schema goes 429 → 4,579 bytes, the `applet` tool 9,183 → 13,333 and the main agent's tool block 41,968 → 46,118 — **+9.9%** on a prompt-cached prefix, ~1,040 tokens written once per session. It cannot be made conditional **on anything turn-scoped** — the narrower claim is the true one, and worth stating precisely because this is where someone trying to shrink the prefix will land. The cache needs the block byte-stable across turns _within_ a session (#269), which is why `createTools` is pure in its arguments; but purity in its ARGUMENTS is exactly what permits argument-driven conditionality, and `opts.surface` already varies this same block that way. A session-resolved flag would preserve byte-stability as `surface` does. It is not built because gating applet authoring hides a capability rather than costing one — not because the door is closed. `nestedOnly` keeps `object` out of level 0, where the expansion is most expensive — justified rather than tuned, since a top-level record is always decomposable into sibling scalar args while inside a variable-length list it is the only way to give an element structure — and a field's `hint` is optional because the deepest level appears four times (hints on `values`/`maxLength` cost ~700 bytes to restate their own names).
      - **The mapping stayed FLAT, which is the per-parameter property surviving intact.** Nesting lives in the TYPE of the source, so `edits: "$.edits"` still names exactly one declared argument and a `dispatch.args` literal is still a scalar; `intraActionRules` needs no recursion. A nested literal would be a second vocabulary — a template language beside the type table, with its own recursion in `mapToolArgs` and in the refinement, kept in step by hand. What it would buy is an author pinning a nested parameter, and the absence of that is not a gap: the caller-supplied alternative is a `z.object().strict()` reconstruction at every level, which is strictly narrower than `file_write`'s `content`, a free string this tier already lets a caller fill.
      - **`schemaVersion` 4, and one function answers both halves.** `schemaVersionDemands` reads `ArgTypeHandler.since`, so a type added later carries its own version demand with no case to remember, and `requiredSchemaVersion` is what `applet.ts` stamps — replacing a `permissions ? 3 : 2` ternary that would have had to learn a third condition. The rule needs a reader (the refinement, which refuses a manifest stamped too low) and a writer, and written twice they drift **silently**: too low and every write is refused, too high and every applet pays its readability to an older binary for a field it does not use. `manifest.version.test.ts` pins them against each other in both directions. **The child walk in `argSpecsSince` is insurance and is currently unobservable** — both containers shipped at revision 4, so a nested demand never exceeds its parent's — and its test asserts that condition rather than pretending to cover it, the `nonIdempotent` precedent.
      - **The starter page was broken for every non-string argument, and the registry is what fixed it.** `run()` read `el.value`, always a string, so a `number` argument was sent as `"5"` and a `boolean` as whatever was typed — both refused by the action's own schema, with a scaffold that looked complete and a button that could not work. Each type now declares a control as **data** (tag, attributes, options, a decoder) and `page-template.ts` stays the only place that turns any of it into markup, so escaping is not something a handler could get wrong. `enum` gets a real `<select>`, `boolean` a checkbox, and a container a JSON `<textarea>` that starts valid; the page script has one generic rule keyed on `data-decode`.
    - **Args are mapped, never passed through.** Each tool parameter names `$.<declaredArg>` or a literal, so a caller's object never reaches a tool wholesale — the same reason `validateActionArgs` is `.strict()`. A reference to an undeclared arg is a **parse-time** error, so a typo is a broken manifest rather than a parameter arriving as the literal `$.dset`.
    - **`src/apps/tool-dispatch.ts` deliberately does not go through `runHeadless`.** That owns MCP connect (~1.1–1.6 s), a RAG store and context assembly, none of which a tool call needs — paying an agent runtime's startup gives back most of what skipping the model saved, and the point of this tier is that it costs nothing. It also does not call `loadConfig`, which throws without a provider API key: an action that makes no model call must not require one (the property `bernard voice-test` also holds; the shell timeout comes from `loadPreferences` so the user's setting still applies). What it **does** keep is `augmentTools`, so the deny, write-scope and confirm gates all fire — skipping the model must never mean skipping the gates, and a test asserts a tool action writing outside its workspace leaves no file. Two things the AI SDK would otherwise have done are done explicitly: the mapped args are `safeParse`d against the tool's own schema (a direct call skips the SDK's pre-execute parse), and an ineligible tool is a **request**-shaped failure (exit 2), not a run failure. Both refusals are **non-throwing** — the gates return an `Error: `-prefixed string — so the result goes through `detectResultFailure` (#363); without it a denial came back as `ok: true` carrying the refusal, and the caller read it as success.
    - **`src/headless-posture.ts` is the leaf both paths share.** `resolvePosture` and `headlessToolOptions` lived in `headless.ts`, which imports `MCPManager`, `RAGStore` and the agent-definition registry — so the module whose whole premise is not paying for an agent runtime was importing **161 ms** of module graph to call a function whose real dependencies cost 3 ms. The other half is that `headlessToolOptions`' security property is what it **omits**: `augmentTools` auto-denies a write under `read-only` when `blockAction` is absent, and an omission cannot be type-checked, so two hand-written copies is how one quietly grows the field and stops failing closed with every test green. Pinned on the tool path by "a read-only action cannot write, with nobody to ask". Measured: the leaf imports in **3 ms** against `headless.ts`'s 169. **Known gap:** the total is unchanged, because `createTools` itself costs ~167 ms — `src/tools/index.ts` statically imports `./cron.js`, which pulls `cron/runner.ts` and the whole agent runtime, even though `surface: 'worker'` never constructs that group. Making the `main`-audience groups' `make()` bodies dynamic imports would recover it for every worker dispatch, not just this one, which is why it is its own change.
  - **Grants are enforced, and it took a third gate (#420).** An app's `toolAllowlist` decides which tools are _constructed_ — `grantedToolNames` intersects it with the specialist's `targetTools`, which is what makes a refused call fail because the tool is absent rather than because the model declined. That stays the primary control; rules cannot express "deny everything else", since `scanRules` answers `'ask'` when nothing matches. The refinement on top is `ProfileSettings.appToolGrants` (`src/apps/app-grants.ts`), `PermissionRule[]` per app, produced only by `bernard app-grant` — **never from the manifest** (the app's own user-editable file, the same reasoning that keeps `skipPermissions` out of the schema) and **never `config.toolPermissions`** (the _user's_ grants; an app inheriting "always allow `shell rm *`" is the confused-deputy widening this exists to prevent). Read per dispatch, so revocation applies to the next invocation with no restart. Absent from every agent-callable tool, like `cron-grant`.
    - **Supplying `getToolPermissions` was necessary and not sufficient.** `resolveProfileGrant` had exactly two callers and both sat behind a short-circuit — `runBlockGate` returns early unless `toolMode === 'read-only'` **and** the tool is a write, `runGate` unless the risk crosses the threshold. An applet runs `read-only` at threshold `high`, so a `deny` on a **low-risk read tool** (`web_search`, `web_read`, `file_read_lines`, `memory{action:'read'}`) matched and never ran. `runDenyGate` is unconditional, shaped like `runWriteScopeGate` (refusal string, not a boolean) and folded with it into one `runUnconditionalGates` so a call site cannot run some of them. Only `deny` is acted on: `allow` keeps meaning "skip the prompt in the gate that would raise one". A rule deny now answers with the rule as the reason rather than borrowing whichever downstream gate caught it — which produced "cancelled by user" when nobody cancelled and "read-only mode" when the mode was not why.
    - `HeadlessPostureInput.toolPermissions` is **required** (`PermissionRule[] | null`), for the reason `writeScope` is: an optional field lets a caller inherit "no rules" by omission. Cron states `null`; `skipPermissions` dissolves it with every other axis. The shell parser is now warmed when rules are present — uninitialised, `parseShellCommand` reports a compound command as `parse-error` and `resolveGrant` matches only a no-specifier `shell` rule, so `deny shell:rm` would miss `ls && rm -rf /`: safe for `allow`, fail-**open** for `deny`.
    - **Every mint is logged (R9).** `CapabilityTable` takes an optional `MintObserver` — a callback, not an import, so the module stays a `node:crypto`-only leaf with no I/O — handed the **record**, never the handle, since `CapabilityRecord.id` exists precisely so a log line need not slice a live credential. Observed in `mint` and not `handleFor`, so a reused designation is not counted as a new capability. `CAPABILITY_LOG_FILE` is a **sibling** of `SCRIPT_LOG_FILE`, not rows in it: that file rotates at 2,000 rows, so interleaved mints would be evicted before the invokes they correlate with — the correlation would be the first casualty under load. The invocation log's `toolsGranted` also now records the **post-intersection** set through the same `grantedToolNames`; it recorded the declared allowlist, which overstates the grant in the one record that is an audit trail.
  - **A design floor that can be checked, not argued (#465).** `/__bernard/tokens.css` was 1,754 bytes and ten properties, and every applet is styled by it and only by it — `style-src 'self'` has no `'unsafe-inline'`, so inline style is discarded by the browser and refused at the write path. That makes the served sheet the one place a design decision reaches every applet at once, and it was too thin to compose from.
    - **`--border` was 1.55:1 on `--bg` and 1.42:1 on `--surface`** against WCAG 1.4.11's 3:1 for a non-text boundary — the one token that was not merely thin but wrong, since a border is how an input's edge is conveyed. Now `#6e7681`, 4.12 / 3.77.
    - **Two failures the issue did not name, both worse.** `button` was `#ffffff` on `--accent` at **2.80:1** — failing AA normal text and even the 3:1 large-text floor, on the most-clicked element of every applet. And `--surface` vs `--bg` is 1.09:1, so a raised panel was delimited only by the failing border. The first is fixed by `--accent-fg`; the second deliberately is not chased — WCAG has no background-to-background rule, and `--border`-vs-`--surface` is the _binding_ constraint of the pair, so lightening the surface would eat the margin on the very check this exists to fix.
    - **`--accent-fg` is the literal `#0d1117`, never `var(--bg)`.** Same value today, different roles: aliasing them would flip button text to near-white on orange the moment a light-mode block changed `--bg` — a 2.1:1 regression from an edit that looks unrelated. That is the one concrete way a token set's SHAPE can be wrong for light mode, and handling it is what makes deferring light mode cheap.
    - **The four states are equiluminant** (7.45–7.51 on `--bg`, a spread of 0.06) so no state shouts louder than another, and one `--accent-fg` clears 4.5:1 on all five solid fills — which is why there are no per-state `-fg` companions.
    - **Three hard-coded hexes were inside Bernard's own floor** (`#f85149` in `.error`, `#ffffff` on `button`, `var(--danger, #f85149)` in the SDK), while `applet-styler` was instructed "Never write a hex colour" — a rule the sheet broke three times and one that was **impossible to obey**, because there was no `--danger`. The SDK line was never CSP-broken, for the record: `style-src` does not govern a CSSOM property setter. It was only a colour in the floor.
    - **`src/color.ts` is a new pure leaf** — parse, luminance, ratio, composite, nearest — because no contrast helper existed anywhere. `parseColor` returns `null` for a named colour or garbage, and **that null is the module's honesty boundary**: a caller must handle it rather than receive a plausible number for a colour nobody parsed. Alpha is **composited, not exempted** (`--accent-dim` over each background), and `contrastOver` returns `null` when the BOTTOM layer is translucent, because what is beneath it is a fact about a paint stack the module cannot see. `nearestToken` measures in **OKLab, not sRGB** — verified on the case that matters: sRGB-Euclidean maps `#f85149`, the exact red Bernard itself hard-coded, to `--accent` rather than `--danger`, and a suggestion that names the wrong token is worse than none because it will be taken.
    - **The check is a test over the served artefact**, not a prompt instruction: no hex outside `:root` (the assertion that would have caught both floor hexes, and what makes the pair table _sufficient_ — a rule body cannot paint a colour the table never measured), the `:root` set equals the record, an `it.each` pair table, and an anti-drift row requiring **every colour token to appear in a row or a reasoned `EXEMPT` set** — the record-to-table direction, the way `bundled-manifest.test.ts` argues for files-to-constant.
    - **Light mode is deferred, and #465's reason for hurrying is wrong.** It says the token set's shape changes; pressure-tested, a `@media (prefers-color-scheme: light)` block renames nothing and every applet writing `var(--x)` adapts free. The genuinely expensive failure is a hard-coded colour in a shipped page — which the enforcement below prevents. _That_ is what buys the option. Two structural commitments make it a data edit: `color-scheme` declared now, and the contrast test iterating a **palette list with one entry**.
    - **A hex WARNS, where #465 asks for a refusal.** Applying `page-validate.ts`'s own rule — certainty, not severity — the two grounds licensing the inline-`<style>` refusals both fail: the false-positive surface is broad and legitimate (`href="#a1b2c3"`, an id, `<meta name="theme-color">`, a canvas colour array, which takes no `var()`), and **the failure is visible** — a hard-coded colour renders. Invisibility is exactly what those refusals turn on. What makes the warning act-on-able instead is the remedy: the nearest token, named.
    - **The `.css` gap was the bigger find.** `validateAppletPage` received only the HTML and **never the `files` map**, so an applet's own stylesheet — the one legal route to real CSS — was written completely unchecked. It now sees `files`, and refuses the two things that fail SILENTLY (a `.css` nothing links, written and served and never loaded; an off-origin `@import` that `style-src` drops with no error) while warning on `url(https://…)`, which a per-applet `img-src` grant can legalise since #467.
    - **No new design specialist, deliberately.** Nothing routes to one: `src/tools/applet.ts` never dispatches a specialist, `bernard app` has no such action, and the only door is `tool_wrapper_run` with a hand-typed id — so a second specialist would reach a _subset_ of what `applet-styler` already reaches, and could not honestly claim hierarchy, balance or rhythm given `applet-reviewer`'s recorded constraint that it cannot see the render. `applet-styler` is updated instead: its enumeration is **pinned to `APPLET_COLOR_TOKENS` by a test** (a prompt that lists tokens is a second copy of the artefact, which is the drift #424 built the served sheet to end), its hex rule is true for the first time, it carries the reviewer's honesty clause, and an instruction that **could not work** is gone — it told the styler to `file_read_lines` the stylesheet, which is generated in memory and never written to disk. Fixing that by writing the sheet out would reintroduce the per-applet copy #424 removed. **The real unlock is routing**, not a better prompt. **Both halves of that objection have since been answered, and differently.** Routing arrived with `styleNote`. The honesty half was never answered for a STYLER and is instead sidestepped by a PLANNER: #13's three planners decide structure — scope, controls, states, store keys, plain HTML vs the runtime — every one of which is decidable from the manifest, the token record and the selector list with no render. So the constraint stands exactly as written, and `applet-ux-planner` carries the same clause verbatim, pinned by the same test.

  - **A runtime for the applets that need one (#466, part 2).** `/__bernard/ui.js` serves Preact + htm — `window.htmPreact`, 13 KB, classic UMD — for the two shapes the measurement showed are written badly by hand: a **list that changes** and **more than about four controls**. Plain HTML stays the default, which is the rule #466 asks for so "the simpler one rots" does not happen.
    - **The CSP eliminated most of the field, and the eliminations were verified in the shipped bundles rather than taken from docs.** `script-src` has no `'unsafe-eval'`. **Vue 3's full global build calls `Function(l)()`** in `compileToFunction`; its clean runtime-only build has no template compiler, so it needs the build step that does not exist, at 41 KB. **Alpine hides the same constructor behind `Object.getPrototypeOf(async function(){}).constructor`**, so grepping for `new Function` misses it, and `@alpinejs/csp` gives up arrow functions, template literals, property assignment and globals. **Shoelace is end-of-life** and its successor shipped four components emitting inline `style="…"` — this exact policy failing in the wild. htm and Preact contain **no dynamic evaluation at all**, asserted by a test over the bytes the route serves, including the indirect spelling.
    - **Resolved through npm, not vendored.** `sdk.ts` and `tokens.ts` are template literals and its stated reason — "a real file would add a `readFileSync`, a `package.json` files entry and a dependency on the dist layout for no gain" — **inverts** for 13 KB of third-party source: pasting it means re-pasting on every upgrade, and the licence stops being visible where licences live. `createRequire(...).resolve` rather than a build-time copy, because resolution works identically under `tsx` and in a global install, so there is no dist layout to depend on and no copy step to forget. It resolves htm's **main entry and walks up**: htm's `exports` map reaches the UMD file only through the deprecated `"./"` catch-all, which modern Node refuses with `ERR_PACKAGE_PATH_NOT_EXPORTED`. Read on first request, so no `bernard script` or cron run pays for a route it will not answer.
    - **Two refusals would have rejected every correct htm page.** `page-validate.ts` refused `<style` and `style=` anywhere in the file, and ``html`<div style="…">` `` inside an inline `<script>` matches both. Script bodies are now masked first — the same masking `colourIssues` already does for comments and `href`/`id`/`name` — and a match **inside** a script warns instead. That is the module's own doctrine applied, not bent: outside a script the finding is certain and the failure invisible, so it refuses; inside one it is uncertain, and if the string really is emitted as markup the CSP drops it and the element renders visibly wrong. A test asserts both directions, because masking too much is how a real inline style slips through.

  - **An applet asks, and the user grants (#467, #468).** An applet is served a deny-by-default CSP, so it cannot load an external image or open a link. Widening that globally was refused on the record already in `csp.ts`: _"`img-src` and `form-action` are exfiltration channels `connect-src` does not cover"_, and an applet holds capability handles and a private store. So the widening is **per applet, per directive, and the user's**.
    - **Three channels, and only one is authority.** A **declaration** (`AppManifest.permissions`, schemaVersion 3) is what the applet ASKS for and why — written by the `applet` tool, i.e. by a model, and it reaches no header. A **grant** (`ProfileSettings.appCspGrants`, `src/apps/app-csp-grants.ts`) is what the user ALLOWED, and it is the only thing `cspFor` reads. **Feedback** (`src/host/violations.ts`) is what the browser BLOCKED, a hint that a grant might be wanted. Pinned by one test: an applet that declares `imgSrc` and holds no grant is served the byte-identical ungranted header. Android is the exact precedent — the app's manifest declares `<uses-permission>`, the OS asks, the OS stores the answer — and it is SEP-1865's rule (_"MUST construct CSP headers based on declared domains"_) with Bernard one step stricter, since declared is necessary here and not sufficient.
    - **A declaration in the manifest is safe precisely because it is not authority**, which is what makes it a different question from `toolAllowlist`. `app-grants.ts`' rule that _"a grant stored there would be settable by the app"_ is about grants; the ask is the app describing itself. Without it a permission prompt has nothing to show, and the alternative is what #467 originally imagined — a line of prose telling the user to go and type a CLI command, which is homework rather than a request.
    - **`src/host/csp-grant.ts` is a pure leaf**: the grantable tables (the `AUTHORITY_ACTION_FIELDS` idiom — a written-down enumeration a test can assert against) plus the parser. **Per-directive separation is structural**: key `k`'s sources are emitted into `DIRECTIVE_NAMES[k]` and nowhere else, so an `img-src` grant cannot widen `connect-src` — stronger than remembering not to. Header splitting gets a grammar **and** a character-class belt, asserted separately, because these strings are concatenated into a response header: a `;` would add a directive nobody granted, and a CR would make `res.writeHead` throw and kill the socket rather than serve the applet. Bare `https:` is accepted **loudly** (#467: it "should be possible but should look as alarming as it is"); bare `http:` is refused, being that breadth plus cleartext.
    - **`cspFor(grant?)` takes the grant optionally, and that is load-bearing.** Every existing assertion in `csp.test.ts` calls it with no argument, so "an ungranted applet is served exactly what it was served before" is a passing test rather than a hope. A grant only ever **appends** — it cannot drop a directive or a sandbox token — and sources are re-validated in `cspFor` as well as at the store, so an in-process caller that hand-builds a grant still cannot widen `script-src`.
    - **Read per request, never cached**, the rule `server.ts` already follows for the manifest (#420 R6). It is what makes a **revoke apply to the next request with no restart** — measured on the live host, and pinned by a test that fails when the header is captured at `startApplet` time. Resolved _before_ the guard, since the grant depends only on `appId` (the server's own closure, never request data), so the refusal path carries the same policy as everything else. A corrupt profile degrades to the ungranted header rather than taking the applet down.
    - **"Allow all" cannot cover `connect-src`.** `src/apps/permission-consent.ts` is pure — three surfaces render the same decision, and a label written three times drifts — and phrases each ask as what the applet does ("Show images from 6 sites"), not as a directive. `PendingPermission.ownScreen` marks the asks that must be answered individually: a two-way channel that can send data out, and any whole-scheme wildcard. The blanket row is the one people press without reading, which is the whole reason for the split; a test fails when the carve-out is removed. The applet's own `reason` is model-written prose being used to influence a security decision, so Bernard renders the structural fact it can verify and quotes the sentence beneath it, attributed — the `<available_sources>` posture.
    - **Fail-closed by omission.** `ToolOptions.requestPermissionConsent` absent means there is nobody to ask, so nothing is granted: the headless path (`bernard script`, cron, tests) and the path a forgotten call site lands on. Denying is a normal outcome — the applet is built either way — and the tool's return says which asks were refused, so the page can degrade rather than render dead frames.
    - **The blocked-request channel is a claim, not evidence.** The page reports through a POST it makes (`securitypolicyviolation` → `/__bernard/violation`), deliberately **not** a CSP `report-uri`: a browser-generated report carries no custom header, so accepting one would mean exempting a path from `guard.ts`'s token check — widening the one gate that keeps every state-changing route honest, for a convenience. Since the applet's own JavaScript decides what to report, the origin is validated through the same parser a grant goes through, anything ungrantable is dropped (a `script-src` violation offers a grant that would not help), the record is a counted map rather than a log because the page controls how often it reports, and **granting is still the user's own keystroke**.
    - **`bernard app csp <id>` is a sibling sub-action, not a flag on `app allow`** — that one is per ACTION (`appId`, `actionName`, `tools`), while a CSP grant is per APPLET and has no action to name, so `bernard app allow demo --img-src X` would collide positionally with `bernard app allow demo greet`. `src/apps/manage.ts` returns where `app-cli.ts` prints (the `apps/open.ts` split), which is what lets `/applets` offer the same operation without writing into Ink's alternate screen buffer. Whole-directive replacement, never append; an invalid source refuses the **whole** write, since a partial grant is the worst outcome available. Warnings repeat on a plain read, because a grant made months ago is the one whose breadth has been forgotten.
    - **`/applets` may delete and grant where the `applet` tool may not, and that is coherent.** The rule in `app-grants.ts` is about the **model** acting; a user selecting a menu row is the same person, with the same authority, as one typing `bernard app delete`. Written down in `App.tsx` because it reads as an inconsistency and would otherwise be "fixed" back.
    - **The service unit forwards `BERNARD_HOME` / `XDG_*`** (`src/host/service.ts`). A login service starts from the session environment, not the shell that installed it, so without this the daemon reads a different `profiles.json` than the CLI writes — and a grant that is stored, printed back, and still not applied is the worst shape a permission bug can take. Pre-existing (it already affected `appToolGrants`); this feature is what makes it visible. An allowlist rather than a copy of the environment, since the unit file is written somewhere user-readable.

  - **`src/apps/store.ts` — one SQLite key-value store per applet (#422).** A **key-value store, not tables and certainly not SQL**: the caller on one side is a browser page reaching in through a capability endpoint, and handing it a query language re-opens exactly what the action-selector design closed. Schema-free, so there is no migration story to get wrong yet. `appletDataDir(appId)` → `DATA_DIR/applet-data/<appId>/data.db` is deliberately **neither** of the two obvious homes: not `appletAssetDir`, which is _served_, so the database would be fetchable over HTTP; not `runWorkspace('apps', appId)`, which is the action's own write scope, so `file_write` could corrupt it out from under the store. WAL plus an explicit 5 s busy timeout are not optional — two processes touch one file and `node:sqlite`'s busy timeout **defaults to 0** — and a test opens two real connections rather than hoping. A `list` prefix is compared with `substr`, never `LIKE`, whose `%` and `_` would make the caller's prefix a pattern. `atomicWriteFileSync` cannot apply to a file SQLite holds open, so the 0600 story is a `chmod` after create; the containing directory is created 0700 first, so the window is inside a directory nothing else can traverse.
    - **`node:sqlite` is loaded through `createRequire`**, the idiom `permissions/shell-ast.ts` already uses. Node excludes experimental modules from `module.builtinModules`, so Vite does not recognise the specifier, strips the `node:` prefix and fails to resolve `sqlite` from disk — a hard load error that stopped a test file being _collected_. The type import is erased, so the types stay real; `npm run build` is `tsc`, which does not bundle, so shipped code was never affected. Its once-per-process `ExperimentalWarning` goes to **stderr**, which both machine-readable callers already tolerate (the daemon is spawned `stdio: 'ignore'`, `bernard script` puts JSON on stdout and diagnostics on stderr). Not suppressed: this repo has no suppression convention, and introducing the first one to hide a true statement about an API's stability is the wrong trade.
    - **Two doors, and neither takes the app id from the caller.** `POST /__bernard/store` (`src/host/store-route.ts`) — **POST for reads too**, because `guard.ts` requires the token only for non-`GET`/`HEAD` so that an asset read works before the page holds one, and applet data is not an asset; a `GET` read route would be reachable by anything that can satisfy the origin checks. And `applet_store` (`src/apps/store-tools.ts`), an action-enum tool bound to one app at construction, modelled on `createScopedCronNotesTools` for the same reason — a store addressed by a call parameter would be ambient authority over every applet's data. It is folded into `buildActionTools` **before** the filter, so a manifest still has to name it and a specialist still has to target it. Both doors share one per-app connection cache (`appletStoreFor`) and one op vocabulary (`applyStoreOp`): the applet host is long-lived and runs both, so a connection opened per dispatch and never closed leaked a descriptor per invocation _and_ put a second writer on a file the route already held open — manufacturing exactly the contention the busy timeout exists to absorb. What legitimately differs between the doors is only the encoding (`value` arrives as JSON text through the tool's string parameter, as a JSON value through the route), so that is all that stays split.
  - **Applets have a write side, and the authority is split (#453).** `AppRegistry` gained `create` / `update` / `remove`, modelled on `SpecialistStore.createFull`: validate id → exists → `MAX_APPLETS` ceiling → atomic write, validating on **write and read** both, since the manifest is user-editable between runs. `create` writes the manifest **and** seeds `appletAssetDir` as one operation — a manifest with no page 404s, and a page with no manifest is invisible to `listIds()`.
    - **The schema does not round-trip, and a writer hits that immediately.** `AppManifestSchema` `.transform`s on read: `liftAction` moves a v1 action's flat `instructions`/`specialistId` into `dispatch`, so re-serializing the parsed output as `schemaVersion: 1` is rejected by the manifest's own refinement. `RawAppManifestSchema` / `parseRawAppManifest` are the un-lifted pair a writer serializes, and `AppManifestSchema` is now that schema plus the transform — so there is one field list, not two that can drift. **Timestamps are deliberately absent**: `SpecialistStore` and `RoutineStore` both stamp `createdAt`/`updatedAt`, but this schema is `.strict()` and adding a field is a schema-version decision. Nothing reads them, so doing without is right.
    - **The `applet` tool can build an applet; it cannot grant one anything.** `app-grants.ts` is CLI-only because _"letting a model widen the authority of the app it is running inside is the escalation the gate exists to prevent"_ — and a manifest's `toolAllowlist` is the **primary** control, strictly more powerful than the grants tool is denied. So the tool writes `id`/`name`/`description`/`actions`/page content, and `toolAllowlist`, `toolMode`, `confirmMode` and **deletion** stay at `bernard app`. A model can therefore build a working applet whose actions are read-only and tool-less by default (the schema already defaults both), and widening it is a user action at a CLI, exactly as granting permissions already is. `audience: 'main'` so a worker never constructs it, and **`directInvocable` deliberately absent** so no applet action can reach it by manifest. `buildManifest` carries the prior authority fields through an update, so an agent edit cannot silently clear a grant the user made. It has a `default:` arm on the action switch because a direct `execute` bypasses zod, and `undefined` would read as success to `detectResultFailure`.
    - **The page half already worked.** `appletAssetDir` is inside no `WriteScope` and the REPL has none, so `file_write` into `APPS_DIR/<appId>/index.html` was an ordinary allowed write from the main agent all along; what was missing was a manifest writer. Inside an applet dispatch it stays correctly impossible — `checkWritePath` confines writes to `runWorkspace('apps', appId)`, and an `AppAction` has no field that can add a path grant.
    - **Deletion sweeps seven places and the order is forced (`src/apps/lifecycle.ts`).** Manifest and assets, `appletDataDir` (**after** `closeAppletStore`, or it races a live SQLite connection), `runWorkspace('apps', id)`, `saveAppGrants(id, [])`, and every specialist with `boundTo.appId === id` — which needed `SpecialistStore.listBoundTo`, because `boundTo` had no reverse index and `getSummaries()` filters bound records out, so a specialist bound to a deleted app was permanently unreachable _and_ undiscoverable while still counting against `MAX_SPECIALISTS`. The **port record is kept, deliberately**: `HostRegistry` has no `release` so a deleted-then-re-added applet gets its origin and with it its browser storage back. That makes dropping `appletDataDir` the one row worth stating twice — keeping the port while dropping the data would hand back the old origin with an empty KV store, a silent half-restore; the coherent options are both or neither, and both is what delete means. The daemon's `reconcile()` already closes the server, revokes capabilities and closes the store when an app leaves `listIds()`, so deletion lets it rather than duplicating it.
    - **The write path refuses a page that cannot work.** Serving the client does not make a generated page use it, and unlike #424's stylesheet the CSP cannot force the issue — every applet writes its own event handlers, so inline script must stay legal. So `page-validate.ts` refuses a page missing either required `<link>`, one carrying an inline `<style>` (which `style-src 'self'` discards in **silence**, so the author sees an unstyled page and no error), one that omits the client while declaring actions, and — the load-bearing check — one that speaks the wire protocol itself, which is what makes the served client the only door. **refuse vs warn is CERTAINTY, not severity**, stated in the module because it is the rule future checks get classified by: a missing `<script src>` is decidable from the string, a dangling `getElementById` may target a runtime-created element. Every refusal has a one-call remedy — `page` is optional and `defaultAppletPage` scaffolds from the actions, pinned by passing its own validator so the rule and the example cannot disagree. Deliberately **not** injecting the missing tags: there is no HTML parser, a regex insert lands inside a comment or template literal, and injection launders the mistake so the next page repeats it.
    - **Eligibility is checked where the manifest is written, not only where it runs.** An applet with `{kind:'tool', tool:'datetime'}` was written, reported as created, and failed at the click with an HTTP 500. `directInvocableRefusalByName` builds a worker-surface registry once per process and delegates to the **existing** `directInvocableRefusal` — not a name list, per that module's own argument that a list disagrees with the tool it describes and the disagreement is fail-open. `toolArgRefusal` closes the sibling hole (a misspelled `pth` for `file_write` was the same 500), checking parameter NAMES and the required set only, since a `$.<arg>` reference's runtime value is unknowable there. **Refuse when the fact is immutable relative to the write, warn when it is user state the next command may change**: eligibility is compiled in, while an unknown `specialistId` is deliberately a warning because the natural order is to create the applet and then bind its agent — which is what `agent-builder` does. **Additive, never a replacement**: a manifest is user-editable between runs, so a write-time check alone is a TOCTOU gap (#420 R6), and a test writes a `datetime` manifest straight to disk and asserts dispatch still refuses it.
    - **`app list` shows the user's own applets by default (#455 follow-up).** A seeded example in one flat list is indistinguishable from the user's own work — the reported symptom was "I tried deleting the old apps and don't know what is what". `--bundled` / `-b` lists only what Bernard ships and `--all` / `-a` groups both; `/applets` splits the same way. **Not hidden, split**: a bundled applet still holds a port and still answers in a browser, so a listing that cannot show it makes it unfindable rather than tidy. `bundledAppIds()` reads the shipped directory rather than a manifest field — the rule `specialist-authority.ts` follows, since a manifest is user-editable and a record that could declare itself bundled would claim provenance it does not have. Unlike a bundled specialist a bundled applet is **not protected**: it is a copy, and the copy is the user's to edit or delete. The listing shows each applet's `description`, which is why the `applet` tool now requires one on create — required by the TOOL, not the schema, which must still read manifests written before this and by hand.
    - **A new applet opens itself**, through `apps/open.ts` — shared, so `bernard app open` is a thin printer over it. It needs **two** waits: the host process binding, and then the daemon noticing the new manifest (`fs.watch` on a 500 ms debounce, then `reconcile()`), so even a running host is not serving a just-created applet when `create` returns. It calls `startHost`, deliberately **not** `appletHostStart` — that one prints and sets `process.exitCode = 1`, and from a tool during a REPL turn the writes land in Ink's alternate screen buffer while a failed open would exit the session non-zero. `canOpenBrowser` is checked rather than attempted, because `openUrl` returns true the moment `spawn` succeeds and `xdg-open` with no display fails asynchronously. `autoOpenApplets` defaults **on** — unlike its `autoCreate*` neighbours — because the defect is "the thing I asked for never appeared"; `create` only, never `update`.
    - **Two bundled specialists, and one of them cannot see what it reviews (#424).** `applet-styler` composes from the served token set — a much easier thing to get right than reproducing hex values from a prompt. `applet-reviewer` verifies **by execution, not by appearance**: `file_read_lines` on the asset directory (the only route to the raw CSS and JS), `probeApplet` to confirm every manifest action minted a handle, and invoking each action and requiring `ok: true` — which is the check that matters, since it exercises the capability path, the `toolAllowlist ∩ targetTools` intersection, the grants and the backing specialist end to end. Its step-2 claim that `bernard script` is "the check that matters ... end to end" was **false and is corrected**: that is a CLI path which never reaches the HTTP server, never presents a token and never runs one line of the page's JavaScript, so a green run and a dead button are compatible — which is how a broken applet shipped. Its prompt **forbids `web_read` by name**: that tool strips `<style>` and `<script>` before conversion and refuses `text/css`, so an agent fetching an applet sees prose with all CSS and all JavaScript deleted, and would confidently review a document it cannot see. It cannot check layout, cascade, contrast or overflow, and the record says so — claiming otherwise is precisely the failure `claim-verifier.ts` exists for. `shell` would let it `curl` raw bytes, but `pac-critic` is explicitly denied `shell` and a review agent that can run arbitrary commands against generated code is the worse trade.
