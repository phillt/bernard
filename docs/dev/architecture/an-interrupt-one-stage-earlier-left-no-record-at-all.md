# An interrupt one stage earlier left no record at all (#478).

- **An interrupt one stage earlier left no record at all (#478).** `#403` established that an Esc landing before the first step still pushes BOTH the user message and the `[interrupted by user]` marker, on the reasoning that a user message with no reply reads on a later resume as a turn the model simply never answered. The pre-turn pipeline is the one window that rule never reached: `runPreTurnPipeline` makes up to three LLM calls — the reference resolver, the prompt rewriter, the recall filter — and both of its abort exits skip `agent.processInput`, which is what pushes the message. So the transcript showed `⏹ Turn interrupted after 3.2s` above **nothing**, and the model was never told anything had been asked. This is consistency with a decision already made, not a new one.
  - **Two of #478's premises are wrong, and both make it smaller than filed.** `PlanStore.cancelAllUnresolved` is NOT uncalled — `plan-enforcement.ts` calls it with `REACT_AUTO_CANCEL_NOTE`, and `enforcePlan`'s doc depends on it, so the interrupt path needed a second, distinct note rather than a first caller. And the typed text is NOT lost: `Prompt.tsx` calls `onRecordInput` **before** `onSubmit`, so one `↑` recalls it, and `Prompt.test.tsx` pins exactly that with a comment reading _"I hit interrupt and the prompt was still there"_. What was missing is the RECORD, not the text — which is also what dissolves the design fork the issue posed, since restoring the buffer would duplicate a recall path that already works.
  - **`Agent.recordInterruptedInput` pushes the RAW input**, because the rewriter may not have run and where it did its output is an LLM-only detail the transcript never shows. It returns the pushed message rather than leaving the caller to find it: identity is the contract for `alreadyOnScreenRef`, the same reason `injectAskUserHistoryMessages` hands its messages back instead of being re-derived by scanning history.
  - **Covered by a flag set at the `processInput` call, not at each exit.** There are two aborts — the `return` after the pipeline and the `throw` from inside it — and both funnel through one `finally`, so a third inherits the fix. It runs **ahead of `persistAgentState` and `commitNewHistory`**, which both sit below it: recording after either would leave the message unsaved or unrendered for the turn that produced it. A test asserts the ordinary post-`processInput` interrupt does NOT call it, since recording there would push a second copy of the user message.
  - **`INTERRUPTED_MARKER` has one owner now**, because there are two producers. Two spellings would be two states the model has to recognise, and only one of them would be in `agent.test.ts`.
  - **The plan is cancelled where the abort is known, and NAMED where it survives.** `processInput`'s abort branch calls `cancelAllUnresolved(INTERRUPT_CANCEL_NOTE)` — the enforcement loop lives inside that same `try`, so the abort throws past it and nothing else would ever move those steps out of `in_progress`. `PlanPanel` already renders `cancelled` with its note, so there is no panel change. But `PlanStore` is per-turn by construction — `processInput` wipes it at the top of the NEXT turn — so the `✘` is erased by whatever the user says next; the durable half is a line folded into the interrupt notice, which is a `staticItem`. #403's own two-records-one-per-audience pattern, with the panel as the live half. Read off `getPlanSnapshot()` filtered on the note, so it can only ever report steps the cancel actually wrote.
  - **The marker is the MODEL's record and must not render as the user's.** `INTERRUPTED_MARKER` lives in `session-markers.ts` and is matched as a whole assistant-role string, because on its own it is a bubble containing nothing but transcript furniture, beside the `⏹ Turn interrupted` notice that already says it in the user's channel — which is the split `App.tsx`'s own comment claims and, until review measured it, did not have. The mechanism predates this change (`agent.ts` already pushed a bare marker and `isSessionScaffolding` did not know the string); what changed is the RATE, from a narrow window after `processInput` to every Esc during a three-call pre-turn pipeline. A marker appended to real partial text is deliberately NOT matched — that text is content.
  - **`INTERRUPT_CANCEL_NOTE` is deliberately not `REACT_AUTO_CANCEL_NOTE`.** That one means "the model was asked to finish this and did not", a statement about the model; this one means "somebody stopped the work". Reusing it would put a reason on the step that never happened.
  - **Making the plan SURVIVE the next turn is deliberately not done.** It needs `PolicyInput` to carry "the last turn aborted" (it takes only `{userInput, config, previousUserInput}`), and `resetPlanOnly: true` is pinned unconditional by two tests. The durable notice meets the acceptance criterion without changing a store documented as per-turn.
  - **The pre-turn window had no test coverage and structurally could not have had any**: `App.test.tsx` mocks `shouldSkipResolver` to `true` and runs with `promptRewriter` and `ragEnabled` off, so Esc always landed after the pipeline. It is a `vi.fn` now so a test can open the window — and the block restores it in `afterEach`, because `clearAllMocks` clears CALLS and not implementations, so a resolver left hanging means `processInput` is never reached in any test that follows (21 of them, when this first landed).
