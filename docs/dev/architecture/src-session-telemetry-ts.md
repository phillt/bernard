# src/session-telemetry.ts

- **src/session-telemetry.ts** — Per-call telemetry sink (`ModelCallTelemetry` JSONL under `logs/telemetry/`). Cost is minted **once**, at record time, by `telemetryFromUsageRecord` — so a model missing from the catalog freezes as `costUsd: null` and renders `n/a` forever, even after the catalog is fixed (311 records, ~$28 of real spend, reported as `$0`). Since #309 `aggregateRecords` **re-prices on read**: `repriceIfUnpriced` recomputes via `priceUsageUsd` and **fills nulls only** — a stored number is the price as it was believed at the time, and re-pricing runs today's catalog against yesterday's call, so blanket re-pricing would silently rewrite history on any vendor price change. The JSONL stays an append-only log; no migration. Records now carry `PRICING_VERSION`, and `aggregateRecords` reports `repricedCalls` + `legacyPricedCalls` which `formatSessionUsageLines` renders as caveats. The legacy flag is keyed on the record **as stored**, not the re-priced copy: what makes a figure suspect is the generation that captured its _token counts_, and a pre-v2 record carries `cacheReadTokens: 0` whether or not input was cached — so a recovered cost inherits the same overstatement (observed 3.04x) and must not be laundered into a confident number by stamping the copy current.
