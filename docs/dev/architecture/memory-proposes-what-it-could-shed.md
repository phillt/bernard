# Memory proposes what it could shed (#529)

- **Memory proposes what it could shed (#529)** — memory only ever grows: `tools/memory.ts` is its single writer, it is model-driven, and until #513 nothing could even express "this one is done". A real install is 30 files / 6,177 chars over five months, roughly 1,000 a month, which reaches the cap in about eighteen — and at the cap #528's filename-ordered drop begins. The cost is per **dispatch**, not per turn: `run.ts` injects the store into every context message, so a turn with three sub-agents pays for all of memory four times. `src/memory-consolidation.ts` is the pass, `src/memory-candidates.ts` the queue.
  - **Measurement reversed the design, and the numbers are the argument.** Sizing every disposition against the real store first: contained duplicates **56 chars (0.9%)**, one-off episodic records **1,801 (29.2%)** — two logs of specific emails sent in May are 1,498 of that — standing rules and contacts the remaining 70%. So deduplication, the obvious framing and the one #529 was filed with, addresses under one percent, and the category worth clearing is 32× larger and is exactly the one needing judgement. Two examples in that issue were also simply wrong and are corrected on it: `issue.md` says _"I gave you the link …"_, which is not the gh-cli rule its two neighbours state, and `email-accounts` / `email-accounts-professional` are **complementary** — one lists work and personal Gmail, the other adds a third account, and neither contains the other.
  - **It proposes; it never writes a memory.** The worker's existing invariant, kept — both sibling detectors `create()` a candidate and touch no user data. **The argument is that a wrongly-retired standing instruction fails silently:** reversibility ("one front-matter line") is worth nothing if nobody notices — the model simply stops seeing _"always check unread only"_ and behaves differently, with no error. A wrong proposal costs a glance. An earlier draft argued instead that the two "cost the same keystroke", since the detached worker cannot print and the next startup is the only announcement point either way; the first half is true and the second is wrong in this design's own favour — "we retired three" costs zero and is ignorable, while a question costs a conversation **and** a per-dispatch context block until answered. It is the asymmetry of the failures that decides it.
  - **`retiredAt` is a separate field from `supersededBy`, not a null.** They are different facts: "X replaced this" points somewhere a reader can follow, "this was never worth keeping" points nowhere — and `supersede()` requires an existing replacement and throws without one, so a one-off record cannot be expressed through it at all. Both are filtered by `listMemory()` on the same terms and undone the same way, by deleting one front-matter line. `retiredAt` joins the front-matter DISCRIMINATORS, and `isRetired` is one predicate rather than two `&&` terms at the filter — a third retirement state added later would otherwise fail **open**, since forgetting the term means the record silently renders. (The discriminator entry is belt-and-braces: `retire()` goes through `readRecord`, which fills `writtenAt` from mtime, so every retired file already carries one — the justification originally given for it cannot fire.)
  - **The gate is `writtenAt`, not a content hash.** #513 already stamps every write, so "has anything changed since we last looked" is answerable from metadata that exists; a hash would be a second mechanism for a question one already answers. The same comparison per record is also the "too fresh to judge" rail — a note written this session has not had time to become redundant, and proposing to retire it is the fastest way to make someone turn the pass off. The marker (`STATE_DIR/.memory-consolidated`) is written even when nothing was proposed, or an unchanged store re-runs the model every session forever.
  - **The spawn gate had to widen, and would otherwise have silenced this entirely.** `index.ts`'s condition was `if (ragStore && history.length >= MIN_HISTORY_FOR_FACTS)`, and `ragStore` is `undefined` unless `config.ragEnabled` — so hanging a MEMORY pass off it means never running for a user with RAG off, a setting with nothing to do with their notes. Consolidation also needs no transcript. `TempPayload.serialized` is optional now and the arms are assembled rather than listed, because they no longer share a gate. One detached child, not two.
  - **Not routed through the LLM sub-call cache, deliberately.** `claim-verifier` records the reasoning for exactly this shape: the key embeds `userContent` verbatim, so a corpus that changes between runs has a structurally zero hit rate while each miss retains a multi-kilobyte key in an uncapped Map for the session. The `writtenAt` gate is the real "don't run again" mechanism.
  - **No confidence score.** `structured-output.ts` states the house rule — _"models are poor at calibrating those"_ — and the two detectors are the exception only because theirs is one term of a composite consumed by `autoCreateThreshold`. Nothing gates on a number here; every proposal is shown. `applet-detector.ts` already records what an unconsumed gate is worth: _"The gate had never once fired."_
  - **Fails closed**, the `claim-verifier` posture rather than `speech-normalizer`'s, on that module's own rule that the choice turns on what the neutral outcome MEANS: here it is a proposal to retire the user's own notes, so unparseable output proposes nothing. `validProposals` is the sole gate in the `correction.ts` advisory/enforcer shape — it drops invented keys, a keeper outside its own group, and two proposals claiming one memory. Semantics are **not** verified there, and the reason is measured rather than asserted — the prompt defines `duplicate` operationally, so a textual gate looks available. Against the store's one true duplicate (`3772` under `issue-3538`, the whole measured 0.9%): normalized substring **no**, token-subset **no**, Jaccard **0.26**. A deterministic gate scores that category at **zero** on the store it exists for.
  - **`memory` gained `retire` and `proposals`, and both had to reach `isWriteAction`.** Omitting either is the fail-open #513 found in `readOnlyWrap` — a new mutating action that no gate classifies is one an unattended dispatch may make with nobody to ask. A bare `proposals` listing is correctly not a write. Pinned by tests in both `tools/memory.test.ts` and `read-only-memory.test.ts`, added on the day the actions were rather than the day someone notices.
  - **The root cause is at the WRITE side, and is one string.** The tool told the model to save _"anything worth recalling later"_, which is what admits "that's an image I uploaded, that can be ignored". It now names what stays true versus what merely happened. Consolidation cures; this prevents, and cannot fix the 30 files already there — which is why both are here.
  - **What `/simplify` changed, because two were bugs rather than cleanups.** (1) The gate stored the **run time** and filtered on it, so the trigger set and the input set were exact complements — a record written this session made `changed` true, was withheld as too fresh, the marker advanced past it, and the next quiet session returned before looking. A user's most recent memory was **never examined**. It stores the inclusion **cutoff** now, with freshness as an age rule, pinned by a two-run test because no single-shot test can catch it. (2) `decision: 'accepted'` had **no reachable production path** — the block instructed the decline and never the accept, so an accepted proposal stayed `pending` and was re-injected next session: the failure `applet-detector.ts` records fixing in the other direction, inherited by copying its block. (3) `RAGStore.cleanupStaleTemp` is static but was reached only through that store's **constructor**, which a RAG-off session never runs — and widening the spawn gate is what made those sessions write payloads into `RAG_DIR`. (4) The corpus was **unbounded**: the store this exists for is the one whose prompt overruns, so the parse would fail closed and the largest stores would silently propose nothing. (5) `tools/memory.ts` value-imported a six-line formatter from the module owning the `generateText` call, putting `ai` + `model-policy` on `tools/index.ts`'s **eager** graph — **51.8 → 12.2 ms** after moving the pure half to `memory-proposal.ts`.
  - **The mutation harness corrupted the tree before it measured it**, and that is worth recording because the failure was silent. Backups keyed on `basename` collided `src/memory.ts` with `src/tools/memory.ts`, so the restore wrote the tool over the store; every run after the first measured a broken tree and the final "restored" line reported 36 failures. Keyed on the full path now. Two of the eleven mutations then went uncaught and both were tests that **could not fail**: a cap asserted with `toBeLessThanOrEqual` against exactly as many inputs as the cap, and a re-retire timestamp compared against one read back from a call in the same millisecond.
