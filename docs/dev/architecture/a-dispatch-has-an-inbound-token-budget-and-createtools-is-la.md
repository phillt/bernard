# A dispatch has an inbound token budget (#451), and createTools is lazy (#452).

- **A dispatch has an inbound token budget (#451), and `createTools` is lazy (#452).** Two round-2 gaps, both about what a dispatch pays before it does anything.
  - **`src/token-estimate.ts`** is the leaf holding `getContextWindow` plus the message estimators. `run.ts` must not import `src/context.ts` — that reaches `generateText`, `config`, `model-policy`, `rag`, `domains` and `image` for a question whose only real dependency is the catalog, the edge `tool-bytes.ts` and `mcp-names.ts` exist to refuse. Measured 7 ms against `context.ts`'s 43. `estimateMessageTokens` was private and would otherwise have been duplicated; `context.ts` re-exports everything, so no caller moved.
  - **The seed check is ephemeral-only, and the asymmetry is deliberate.** The main agent already runs its own preflight `emergencyTruncate` with the COMPLETE prefix — the per-turn context message included, which the framework cannot see at that point — so checking there too would double up on the one definition that does not need it, using the worse estimate. `SEED_BUDGET_RATIO` is 0.8 against the preflight's 0.9 precisely because this one has an incomplete prefix and can only refuse where that one can truncate. The under-count is stated in the doc rather than papered over.
  - **`createTools` is async, and the nine `main`-audience tool modules load only when constructed.** The `ToolGroup` table's laziness was always the design, but it was _construction_-time laziness and the static imports at the top of `tools/index.ts` happened first: a worker surface paid **167 ms** of module graph to build a registry in **0.20 ms**. Measured after: `tools/index.js` **79 ms**, and — via a second deferred edge — `bernard script` **163 → 17 ms**, because `apps/invoke.ts` statically imported `dispatch.ts` and so loaded the whole agent runtime _before_ reaching the `kind === 'tool'` branch that exists to avoid it. The remaining floor is dominated by `web.js` (64 ms), which is `audience: 'any'` and unreachable by the surface filter.
  - **Deferring one edge turned a load-time cycle into a call-time one, and that deadlocked.** `tools/index.ts` → `cron.ts` → `cron/runner.ts` → `framework/agents/index.js` → `main.ts` → back to `tools/index.ts`. ESM resolves that at load; resolved at _call_ time under `vi.resetModules()` it hangs — 60 s and still going, while plain Node built all 21 tools in 173 ms. The fix is the one `delegate.ts` already documents: `cron.ts` defers `runJob` to its `execute`, which breaks the cycle and drops `cron.js` from 160 ms to 45 as a side effect. **A dynamic import across an existing cycle is not a free substitution for a static one.**
  - `RunHeadlessOpts.buildInput` is now `TInput | Promise<TInput>` — `apps/dispatch.ts` assembles its registry inside it, and it was the single genuine blocker; six of nine `createTools` callers needed nothing, since `AgentDefinition.tools()` already returned `T | Promise<T>` and `runDefinition` already awaited.
