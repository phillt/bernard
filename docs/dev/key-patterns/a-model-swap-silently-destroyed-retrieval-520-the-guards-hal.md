# A model swap silently destroyed retrieval (#520, the guards half).

- **A model swap silently destroyed retrieval (#520, the guards half).** `cosineSimilarity` returns `0` when two vectors differ in length, `0` is below every threshold, so `search()` returned `[]` — **no error, no log**, a store of 3,586 facts reading as empty. And `dimensions()`, the interface method that exists to catch exactly this, had **zero production callers**: declared, never wired. This is its first.
  - **Worse than the issue states.** `DIMENSIONS = 384` is used to **slice the flat output buffer**, so a different model's own fresh output would be cut into garbage vectors — not merely mismatched against stored ones.
  - **Refuse, do not discard — the one deliberate inversion of the template.** `CACHE_SCHEMA_VERSION` (`providers/catalog.ts`) is the shape to copy, but its mismatch path returns `null` and refetches, which is right for a disposable model catalogue and wrong here: these are thousands of records derived from the user's own conversations. A mismatch stops retrieval, says which model wrote the store and which is active, states that the facts are intact, and leaves re-embedding or an explicit `bernard facts clear` as the user's call. Said once per process through `console.error` — `debugLog` alone would reproduce the original defect one level up, since the whole failure was that it was invisible without `BERNARD_DEBUG`.
  - **No migration script.** The file was a bare array and `load()`'s `Array.isArray(parsed)` guard was already the legacy arm, so `{version, model, dimensions, memories}` reads back compatibly and a legacy store is adopted, stamped and written on the same constructor pass. Verified against a copy of the real store: 3,586 records adopted, stamped in place, search unaffected. **A model swapped _before_ the stamp existed cannot be detected** — a real assumption, not an oversight.
  - **The refusal is STATE, not a print.** `retrievalDisabledReason()` records why retrieval is off and this module prints nothing. `console.error` is the obvious channel and is the wrong one: search runs mid-turn (`recall-filter`, the main agent's own retrieval), and in the default full-screen REPL Ink owns the alternate screen buffer — a raw stderr write at the cursor corrupts the current frame and is overwritten on Ink's next ~32 ms render, so the warning deliberately made "loud enough to be seen" would be the one **least** likely to be seen. `catalog-notice.ts`'s `provider-wiped` precedent exactly, and for its stated reason: "every search is returning nothing" has to outlive a keystroke. So the REPL pushes a **transcript notice** beside the memory-cap one, and `runHeadless` writes it to the **run log** — which for cron is the job log an operator reads later, and without which an unattended job answers worse forever and says nothing. Non-null is also the once-per-process latch, so each front end announces it once however many searches ran, and the test asserts the store prints NOTHING rather than asserting a message.
  - **The refusal lives in `embedQuery`**, the one choke point `search` and `searchWithIds` both pass through, so it is written once rather than at each entry point.
  - **Both halves of the mismatch are compared**, and the dimensions half needed its own test: the realistic swap #520 names is a Matryoshka model truncated to fewer dimensions, which keeps its id and changes its vector length. Comparing the name alone lets that through.
  - **The truncation ceiling is 256 word pieces, not 512**, and correcting that matters beyond this file — #515, #517 and #518 are all being shaped around the number. Nothing warned when input passed it: the tokenizer truncates silently and `embed` returns a well-formed vector for a prefix. The existing caller-side bounds are already comfortably over it (two at 1,000 characters, `facts-cli` at 10,000 — roughly twenty times), so today's "bounds" are routinely truncated with nobody told. A warning rather than a refusal or a caller-side cut: a prefix embedding is still useful, and what was missing is that the ceiling was invisible. Once per process, because this runs in a loop over every fact.
  - **The semantic response cache was flagged as a second victim and is not one.** It reuses the same comparison, but its vectors never persist — entries are built in-process by the one cached provider and expire in ten minutes — so there is no cross-model mismatch to guard. Recorded because the guard looks obviously right and would have been dead code.
  - **The model _decision_ is untouched.** #520's other half — whether to swap at all, and to what — is research that shapes three downstream issues, and stays open.
  - **Doc drift fixed in the same PR**, because it undercuts the change: the README and `docs/domain-specific-memory.md` said in seven places that embeddings come from **fastembed**, which the code has not used since it moved to `@xenova/transformers`. A PR whose point is making "which model produced this store?" answerable cannot leave seven places answering it wrongly.
