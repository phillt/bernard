# Agent-pool slots (#317)

- **Agent-pool slots (#317)** — `withSlot(fn, onExhausted)` (`src/tools/agent-pool.ts`) owns acquire _and_ release for five call sites (`subagent`, `task`, `specialist-run`, `tool-wrapper-run`, and the REPL's `/task`); `withUncappedSlot(fn)` serves the sixth, `delegate-dispatch`. `releaseSlot` took no argument, so a hand-paired acquire/release could drift silently rather than throw. **Nesting is inferred, not declared**: an acquire from inside a slot-holder is free, tracked by a dedicated `AsyncLocalStorage<number>` in that module — the store carries the DEPTH, so `MAX_DISPATCH_DEPTH` and the nesting exemption derive from one value and cannot drift. It deliberately does **not** key on `getCurrentDispatchId()` — `runWithDispatchId` is established for every dispatch and the AI SDK invokes `tool.execute` inside it, so that test would exempt every ordinary sub-agent acquire, which is the cap's entire purpose. Holding a slot and being inside a dispatch are different facts. `onExhausted` is a thunk rather than a discriminated return because the call sites report exhaustion in four shapes (bare string ×2, `err()` envelope, `pool_exhausted` `WrapperResult`, a toast), each dictated by its tool's own return contract and asserted verbatim by tests — they already converge where it matters, since `error-taxonomy.ts` classifies all of them as `pool_exhausted`. **`withUncappedSlot` exists because the ALS is not sufficient**: delegation must never be starved, and the main agent holds no pool slot at all, so a `delegate_*` call issued by _main_ is not ALS-nested — routing it through the capped path would let four parallel sub-agents starve main's own MCP access, the exact failure #305 fixed, and a regression #317 would otherwise have introduced while removing the old unconditional `nested: true` bypass. Two consequences: nested slots are still counted (so release stays symmetric and `getActiveCount()` may exceed the cap — no longer bounded at +1, since the exempt set grew from one declared path to every dispatch below a slot-holder), and **the cap bounds neither depth nor width** — a nested acquire is exempt, so a chain passes straight through it. Depth is counted separately by `MAX_DISPATCH_DEPTH` (`BERNARD_MAX_DISPATCH_DEPTH`), which exists because that sentence used to claim otherwise.
