# Grounding in AI Agent Systems

Research notes for Bernard. Primary sources preferred; secondary commentary marked as such.

**Date:** 2026-08-31  
**Scope:** “Grounding” as used for LLMs and tool-using agents (not robotics symbol grounding alone, though that lineage is noted).

---

## 1. Definition

“Grounding” is overloaded. Three related senses appear in primary literature and product docs:

### 1.1 Source / knowledge-base grounding (LLM product + eval sense)

Kenthapadi, Sameki, and Taly (KDD 2024 survey) define **grounding for LLMs** as:

> ensuring that every claim in the response generated by an LLM can be attributed to a document in the **user-specified knowledge base**.

They explicitly distinguish this from general **factuality** (truth w.r.t. the world): a response can be factually true yet **ungrounded** if it is not supported by the provided corpus, and grounded claims can still be wrong if the corpus is wrong.  
Source: [arXiv:2407.12858](https://arxiv.org/abs/2407.12858) / [ar5iv HTML](https://ar5iv.labs.arxiv.org/html/2407.12858)

Google Vertex AI uses a similar product definition: **grounding** connects model output to verifiable sources of information (Google Search and/or Vertex AI Search corpora) so answers can include supporting links/citations and stay tied to enterprise or web data.  
Source: [Vertex AI — Grounding overview](https://cloud.google.com/vertex-ai/generative-ai/docs/grounding/overview)

Anthropic’s Citations API is framed the same way: Claude **grounds answers in source documents** and returns sentence/passage-level references for claims inferred from those sources.  
Source: [Introducing Citations on the Anthropic API](https://www.anthropic.com/news/introducing-citations-api) · [Citations docs](https://docs.anthropic.com/en/docs/build-with-claude/citations)

### 1.2 Cognitive / AI grounding (broader theory)

Liu (2023) defines grounding more generally as:

> the process of connecting **abstract knowledge** … to **concrete experiences / the external world / sources**.

For LLMs he highlights **source grounding**: linking generated answers to correct, up-to-date information via **creditable sources** (as opposed to purely parametric memory). He notes the “prevailing definition of LLM grounding” as connecting answers to supporting evidence, and situates it inside a larger framework that also includes sensorimotor / world grounding from classical AI and cognitive science.  
Source: [arXiv:2312.09532](https://arxiv.org/abs/2312.09532) — _Grounding for Artificial Intelligence_

### 1.3 Agent / tool-result grounding (systems sense)

In tool-using agents, grounding usually means: **claims and next actions are conditioned on actual tool observations** (search hits, file contents, API JSON, shell output, browser DOM), not on the model’s prior alone. This is the operational form of source grounding when the “documents” are **live tool results**.

ReAct (Yao et al., 2022) is the canonical formulation: interleave **Reason** traces with **Act** (tool calls) so the model can pull external knowledge and reduce hallucination versus chain-of-thought alone.  
Source: [arXiv:2210.03629](https://arxiv.org/abs/2210.03629)

**Working definition for Bernard-style agents:**

> A response (or plan step) is **grounded** when each material claim is attributable to a checked artifact this turn—retrieved doc, tool result, file, memory entry, or user message—and unattributable claims are marked uncertain, abstained, or explicitly unverified.

That matches both the Kenthapadi attribution standard and agent practice (cite tool results; don’t narrate fake command output).

## 2. Why it matters

| Risk                           | Why grounding helps                                                                                      | Primary pointer                                                                                                                                             |
| ------------------------------ | -------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Hallucination**              | Models generate fluent falsehoods; tying claims to sources makes errors detectable and often preventable | OpenAI: [Why language models hallucinate](https://openai.com/index/why-language-models-hallucinate/) · [arXiv:2509.04664](https://arxiv.org/abs/2509.04664) |
| **Trust / verification**       | Users (legal, finance, support) need _where_ an answer came from, not only the answer                    | Anthropic Citations; Thomson Reuters / Endex case notes on same page                                                                                        |
| **Stale parametric knowledge** | Weights lag the world; retrieval/tools supply current facts                                              | Lewis et al. RAG [arXiv:2005.11401](https://arxiv.org/abs/2005.11401); Vertex grounding overview                                                            |
| **Agent reliability**          | Ungrounded agents invent file paths, PR statuses, email contents, “successful” commands                  | ReAct motivation; Toolformer [arXiv:2302.04761](https://arxiv.org/abs/2302.04761)                                                                           |
| **Eval misalignment**          | Accuracy-only scoreboards reward guessing; humility/abstention is under-rewarded                         | Kalai et al. 2025                                                                                                                                           |
| **Safety & compliance**        | High-stakes domains need observability: what source justified what action                                | Kenthapadi et al. survey (trustworthiness, observability)                                                                                                   |

OpenAI’s 2025 analysis is especially important for _why_ the problem persists: pretraining is next-token prediction without true/false labels (so arbitrary facts are statistically hard), and **post-training evals often reward confident guesses over “I don’t know.”** Grounding mechanisms (tools, RAG, citations) are mitigations; fixing eval incentives is a complementary socio-technical fix.  
Source: [openai.com/index/why-language-models-hallucinate](https://openai.com/index/why-language-models-hallucinate/) · [arXiv:2509.04664](https://arxiv.org/abs/2509.04664)

## 3. Mechanisms

### 3.1 Retrieval-Augmented Generation (RAG)

Lewis et al. (2020) combine a **parametric** generator with a **non-parametric** retriever over an external index so the model conditions on retrieved passages for knowledge-intensive tasks. This is the backbone of “ground answers in a corpus.”  
Source: [arXiv:2005.11401](https://arxiv.org/abs/2005.11401)

Kenthapadi et al. treat RAG as a primary **grounding** approach: retrieve → condition generation → (ideally) attribute spans to retrieved docs.

**Product forms:**

- **OpenAI file_search** — retrieve from vector stores; responses can include **file citation** annotations pointing at underlying files/chunks.  
  Source: [File search guide](https://platform.openai.com/docs/guides/tools-file-search)
- **Google Vertex AI grounding** — Grounding with Google Search and/or Vertex AI Search; model outputs tied to returned source metadata/links.  
  Source: [Grounding overview](https://cloud.google.com/vertex-ai/generative-ai/docs/grounding/overview)
- **LlamaIndex CitationQueryEngine** — retrieval + synthesis that aims to emit citations to source nodes.  
  Source: [Citation query engine API](https://docs.llamaindex.ai/en/stable/api_reference/query_engine/citation/)

### 3.2 Native citation / attribution APIs

**Anthropic Citations:** documents are chunked (default: sentences, or user-provided chunks); the model returns citations tied to chunks for claims derived from sources; Anthropic reports higher recall vs many prompt-only citation schemes; customers report fewer “source hallucinations.”  
Sources: [announcement](https://www.anthropic.com/news/introducing-citations-api) · [docs](https://docs.anthropic.com/en/docs/build-with-claude/citations)

This is grounding **as a first-class decoding/API feature**, not only a prompt convention.

### 3.3 Tool use / agent loops (tool-result grounding)

| Pattern                         | Idea                                                                     | Source                                               |
| ------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------- |
| **ReAct**                       | Interleave reasoning with tool acts; observations re-enter context       | [arXiv:2210.03629](https://arxiv.org/abs/2210.03629) |
| **Toolformer**                  | Self-supervised learning of when to call APIs (calculator, search, etc.) | [arXiv:2302.04761](https://arxiv.org/abs/2302.04761) |
| **Assistants / agent runtimes** | Model must call tools; policy forbids fabricating tool output            | OpenAI tools docs; agent frameworks generally        |

For local agents (Bernard-class): shell, `gh`, file read, browser, email MCP, etc. are the grounding channel. **Evidence pointers** (cite the tool result that proved a claim) are the systems analogue of RAG citations.

### 3.4 Constrained decoding & guardrails

Kenthapadi et al. also list:

- **Constrained decoding** — limit tokens to those consistent with a grammar, schema, or allowed span set (e.g. only emit entities that appear in retrieved text).
- **Guardrails / post-checks** — NLI or entailment models that test whether each claim is supported by evidence; revise or refuse if not.
- **Corpus / continual tuning** — improve the knowledge base or fine-tune so parametric behavior aligns better (still not a substitute for attribution).

### 3.5 Uncertainty, abstention, and eval design

Kalai et al.: hallucinations are not only a retrieval problem; **grading that punishes abstention** trains models to bluff. Mechanisms that help:

- Explicit **“I don’t know” / ask user** paths when evidence is missing
- Scoring that penalizes confident errors more than uncertainty
- Separate metrics: accuracy vs error vs abstention (see their SimpleQA-style discussion on the OpenAI blog)

### 3.6 Faithfulness evaluation (measuring grounding)

Common automatic checks (ecosystem practice; often LLM-as-judge):

- **Faithfulness / groundedness:** is each claim supported by the supplied context?
- **Citation precision/recall:** do cited spans actually support the sentence?
- **Answer relevance:** did retrieval bring the right docs at all?

LangChain/LangSmith historically document RAG eval cookbooks along these axes (faithfulness vs answer relevancy vs context quality). Treat framework docs as implementation references, not foundational theory.  
Related entry point (may move over time): LangSmith RAG eval cookbooks under docs.smith.langchain.com

## 4. Failure modes

| Failure mode                          | What happens                                          | Why it breaks grounding                                               |
| ------------------------------------- | ----------------------------------------------------- | --------------------------------------------------------------------- |
| **Retrieval miss / wrong chunk**      | Right answer not in top-k; or distractor docs win     | Model “grounds” on irrelevant text or falls back to priors            |
| **Faithful to bad sources**           | Corpus outdated, wrong, or adversarial                | Grounded ≠ true (Kenthapadi distinction)                              |
| **Source hallucination**              | Cites doc/page/line that doesn’t contain the claim    | Attribution theater; Anthropic/Endex explicitly optimize against this |
| **Partial attribution**               | Some sentences cited, key inferences not              | User over-trusts the whole answer                                     |
| **Tool result ignored**               | Agent called the tool but answered from memory anyway | Classic agent bug; violates tool-result grounding                     |
| **Fabricated tool success**           | Narrates `git push` / test pass without running it    | Ungrounded side effects; dangerous in CLI agents                      |
| **Stale observation**                 | Uses old tool output after world changed              | Temporal ungrounding                                                  |
| **Context overflow / lost-in-middle** | Evidence was retrieved but buried; model drops it     | Soft retrieval failure                                                |
| **Over-constrained decoding**         | Only copy spans → incomplete or awkward answers       | Utility vs faithfulness tradeoff                                      |
| **Eval-driven bluffing**              | Model guesses to maximize accuracy score              | Kalai et al.: structural incentive to ungrounded confidence           |
| **Multi-hop gaps**                    | Each hop weakly supported; chain not entailed         | Claim looks cited but isn’t deductively grounded                      |
| **Cross-doc contradiction**           | Two sources disagree; model merges silently           | Missing conflict handling                                             |
| **Prompt-injection via “sources”**    | Retrieved web/tool text contains instructions         | False grounding channel (treat tools/web as data)                     |

## 5. Open questions

1. **Unified metrics** — How should systems jointly score _world-factuality_, _corpus faithfulness_, _citation correctness_, and _calibrated abstention_? No single leaderboard does this well (Kalai; Kenthapadi).

2. **When to retrieve vs act vs abstain** — Optimal policies for tool budget, latency, and risk are still heuristic (ReAct-style loops help but don’t solve cost/safety).

3. **Native citation vs prompt citation** — API-level citations (Anthropic) beat many prompt hacks on recall, but portability across models/providers and long agent traces is open.

4. **Grounding long-horizon agents** — Multi-step plans accumulate unverifiable intermediate beliefs; how to re-ground continuously without drowning context?

5. **Training objectives** — Can pretraining/post-training directly optimize _supportability_ (entailment by evidence) rather than only next-token or preference win-rate?

6. **Eval reform adoption** — Kalai et al. argue dominant accuracy benchmarks must change; whether the industry rewrites scoreboards remains open.

7. **Adversarial and poisoned corpora** — Grounding to a compromised KB or search index can _increase_ harm by laundering falsehoods with citations.

8. **Human-level source quality** — Classical grounding (Liu) asks for connection to world/experience; LLM source grounding stops at documents. Bridging to sensors, UIs, and real side effects (true agent grounding) is incomplete.

9. **Privacy / IP** — Citing and logging source spans for audit can leak sensitive retrieved content; governance vs verifiability tension.

10. **Cross-tool provenance standards** — No widely shared schema for “this sentence ← that tool result field” across runtimes (compare OpenAI file_citation annotations vs Anthropic citation blocks vs Vertex grounding metadata).

## 6. Implications for Bernard (practical)

Not required by the prompt, but maps research → this codebase:

- **Citation / evidence rules** already encode source grounding: factual claims need `[^Sn]` from tools/files/web; else `[unverified]` or `ask_user`.
- **Never fabricate tool execution** is tool-result grounding as a hard invariant.
- **RAG-like memory/recall** is weak grounding unless the turn re-reads the artifact (recalled context is hint data, not authority).
- Prefer **read-back verification** after mutations (ground the claim “it worked” in a fresh observation).

## 8. Short synthesis

**Grounding** in modern LLM/agent systems means **tying each material claim to checkable evidence**—a user KB, web/enterprise search hit, or tool observation—and failing closed (abstain, ask, or mark unverified) when evidence is missing. It is **stricter than fluency** and **different from world-factuality**. Mechanisms span RAG, citation APIs, tool loops, constrained decoding, and faithfulness checks; failures span bad retrieval, fake citations, ignored tools, and eval-driven guessing. The live research edge is less “call a search tool” and more **reliable attribution, calibrated uncertainty, poisoned-source resistance, and long-horizon provenance** under real agent workloads.
